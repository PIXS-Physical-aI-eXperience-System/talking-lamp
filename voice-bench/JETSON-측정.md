# Jetson 실측 — 음성 파트 최종 구성

파트 C(음성) / 최승원 · 2026-09-06
대상: Jetson Orin Nano 8GB / JetPack R39 / Ubuntu 24.04 / Python 3.12 / CUDA 13.2

맥에서 고른 후보를 실제 보드에서 다시 잰 기록이다. **맥 CPU 기준으로 내렸던
결정 두 개가 여기서 뒤집혔다.**

---

## 최종 구성

| | 구성 | 근거 |
| --- | --- | --- |
| **STT** | faster-whisper **small** / CUDA / `int8_float16` | RTF 0.35, CER 0.000 |
| **TTS** | MeloTTS ONNX **VITS fp32 + BERT int8** / CUDA | RTF 0.251 |
| **런타임** | 직접 빌드한 sm_87 휠 2종 | PyPI 에 없음 |
| **합성 방식** | 문장 단위로 쪼개서 합성 | 메모리 −505 MB, 첫 소리 7.7배 빠름 |

### 메모리

| 상태 | 사용량 | 빈도 |
| --- | --- | --- |
| 유휴 (대기) | **~1.1 GB** | 대부분의 시간 |
| 대화 중 | 1.25~1.4 GB | 말하거나 들을 때 |
| **barge-in (최악)** | **~1.55 GB** | 말을 끊고 들어올 때 |

**팀 요청: 1.8 GB** (웨이크워드·VAD·오디오 버퍼 약 200 MB 미포함분 + 여유)

### 지연

30턴 반복 시험: 중앙값 **1.79s**, p95 **2.19s**, 최대 2.65s.
한 턴 = STT + TTS 이며 **VLM 시간은 빠져 있다.**

---

## 뒤집힌 결정 1 — TTS int8은 GPU에서 쓰면 안 된다

맥 CPU 에서는 int8 이 주력이었다. Jetson GPU 에서 같은 모델·같은 문장으로:

| | RTF | 피크 |
| --- | --- | --- |
| int8 + CUDA | **2.61** | 1599 MB |
| fp32 + CUDA | **0.250** | 2236 MB |

**10.4배 차이.** 동적 양자화는 CPU 커널용 최적화라 CUDA 에 대응 커널이 없는
노드가 CPU 로 폴백하고, 그 경계마다 int8↔fp32 변환이 붙는다. 작게 만들면
빨라진다는 가정이 GPU 에서는 성립하지 않는다.

### 단, BERT 만은 int8 이 공짜다

melo 에는 모델이 둘 있다. **VITS**(파형 생성, 162 MB)와 **BERT**(억양 결정, 395 MB).

| | 속도 영향 | 메모리 |
| --- | --- | --- |
| VITS int8 | 10.4배 느려짐 | — |
| **BERT int8** | **+0.3%** (측정 잡음) | **−772 MB** |

같은 폴백이 일어나지만 BERT 는 문장당 한 번만 돌고 전체 연산에서 차지하는
비중이 작다. 음질은 청취 확인했다(승원).

`--bert-int8` 을 쓸 것. `--int8` 은 VITS 까지 내려가므로 **쓰면 안 된다.**

## 뒤집힌 결정 2 — STT는 CPU로 못 돌린다

| 스레드 | 추론 | RTF | CER |
| --- | --- | --- | --- |
| 2 | 37.6s | 2.00 | 0.000 |
| 4 | 22.1s | 1.17 | 0.000 |
| 6 | 20.1s | 1.07 | 0.000 |
| **CUDA** | **6.6s** | **0.35** | **0.000** |

6코어를 전부 써도 실시간이 안 된다. 실제로는 비전·움직임과 나눠 써야 하니
4코어 기준 1.17 로 봐야 한다. **모델은 처음부터 맞았고 실행 경로가 틀렸다.**

`base` 로 내리는 선택지는 없다. 심사 문장 6개 중 4개가 틀렸고(CER 0.148)
"승원아, 3시에 회의 있어" 를 "뭐 나 센시也可以 있어" 로 냈다.

## 런타임을 직접 빌드해야 했던 이유

PyPI 의 aarch64 휠 두 개가 모두 Jetson 에서 못 쓴다.

| 패키지 | 문제 | 해결 |
| --- | --- | --- |
| onnxruntime-gpu | sm_87 커널 없음 → `cudaErrorNoKernelImageForDevice` | `build-onnxruntime/` |
| ctranslate2 | CUDA 없이 빌드됨 → `not compiled with CUDA support` | `build-ctranslate2/` |

둘 다 CUDA 13.0 으로 빌드했다. Jetson 은 13.2 지만 NVIDIA 의 마이너 버전
호환 규칙에 따라 동작한다 — 13.2 로는 onnxruntime 이 CCCL 헤더 충돌로 죽었다.

## 긴 발화·긴 답변

**사용자 발화 길이는 걱정할 필요가 없다.** 60초를 말해도 +103 MB 이고 RTF 는
오히려 좋아진다(0.22 → 0.08). 고정 비용이 분산되기 때문이다.

**램프의 답변 길이가 문제다.** 그건 VLM 이 정하므로 우리가 통제할 수 없다.
138자(오디오 27초)를 통째로 합성하면:

| | 통째로 | 문장 단위 9조각 |
| --- | --- | --- |
| 최고 메모리 | 1750 MB | **1245 MB** |
| 유휴 대비 | +655 MB | **+95 MB** |
| 말 시작까지 | 4.56s | **0.59s** |
| 전체 합성 | 4.56s | 7.22s |

VITS 는 파형 전체를 한 번에 만들어서, 긴 출력이면 중간 텐서가 그만큼 커진다.
전체 합성 시간이 느는 것은 문제가 안 된다 — 첫 조각을 재생하는 동안 다음을
만들면 되고, RTF 0.17 이라 합성이 재생을 계속 앞지른다.

**긴 답변은 반드시 문장 단위로 쪼개서 합성할 것.**

## 측정 도구

| 스크립트 | 용도 |
| --- | --- |
| `bench/stt_sweep.py` | STT 모델·스레드별 RTF 와 CER |
| `bench/mem_profile.py` | 구간별 메모리. barge-in 겹침 포함 |
| `bench/e2e_test.py` | N턴 반복. 누수와 지연 흔들림 |
| `bench/long_utterance.py` | 긴 발화·긴 답변에서의 메모리 |

메모리는 **피크 RSS 가 아니라 `/proc/meminfo` 기준 시스템 사용량**으로 잰다.
피크 RSS 는 한 번 올라가면 안 내려가서, 이미 반납된 메모리를 다음 구간에
더한 것처럼 보인다(그래서 초기에 3263 MB 라는 과대값이 나왔다). 통합 메모리라
GPU 가 잡아간 몫도 시스템 사용량에는 잡힌다.

## 아직 확인하지 못한 것

- **VLM 과 GPU 를 동시에 쓸 때** — 통합 메모리라 서로 밀어낼 수 있다. A·D 파트와
  같이 돌려봐야 안다. 지금 숫자는 전부 음성만 돌린 상태다.
- **긴 시간 누수** — 30턴에서는 안정이었으나(변동 −1 MB), 턴당 1~2 MB 씩 새는
  것은 이 표본에서 잡음에 묻힌다. 200턴 이상을 밤새 돌려야 한다.
- **마이크·웨이크워드·VAD** — 마이크 미도착, 웨이크워드 학습 전.
  현재 숫자는 "음성 파트 전체"가 아니라 **"STT·TTS"** 다.
