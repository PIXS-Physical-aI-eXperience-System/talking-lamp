# 프로젝트 상황 VLM 벤치 (2026-09-15)

## 결론

현재 경량 경로인 **InternVL3.5-1B HF + bitsandbytes NF4 + 1타일**은 PC
RTX 5070 Ti에서 추론당 CUDA allocated 피크가 **1.086GB**이고 평균 추론 시간은
**1.17초**였다. 같은 조건의 2B보다 allocated 피크가 **1.154GB(51.5%)** 작다.

하지만 장면 이해, 한국어 대사, 행동 예약어 선택을 한 번에 요구한 프로젝트 게이트는
1B가 **0/7**, 비교용 2B가 **1/7**이었다. 1B는 JSON 스키마와 예약어 allowlist는
7/7 지켰지만, 시각 핵심 개념은 2/7만 검출했고 모든 장면에서 `idle`만 골랐다.
따라서 1B를 자유형 L2 판단기 전체로 바로 연결하는 것은 부적합하다. 기존에 검증한
**짧은 영어 시각 사실/닫힌 라벨 추출**까지만 1B에 맡기고, 한국어 렌더링과 행동
선택은 규칙 또는 별도 텍스트 단계로 분리하는 구성이 현재 근거에 맞다.

## 무엇을 시험했나

저장소의 실제 사진 4장에 질문 7개를 적용했다. 단순 물체 나열을 넘어 Talking Lamp가
필요로 하는 범위와 경계를 포함했다.

| 케이스 | 확인하려는 능력 | 입력 |
|---|---|---|
| `power-strip-multi-object` | 여러 물체와 연결 관계 | 멀티탭·충전기 사진 |
| `robot-workbench-context` | 어지러운 작업대의 프로젝트 맥락 | 로봇 램프 작업대 |
| `hand-circuit-assembly` | 손과 부품으로 사용자 행동 추론 | 회로/헤드 조립 사진 |
| `lamp-user-interaction` | 사람-램프 공간 상호작용 | LeLamp 실사용 사진 |
| `fine-text-diagram` | 작은 글자와 부품 도면 이해 | 5축 램프 도면 |
| `absence-boundary` | 사람 없음 판단의 한계 | 사람이 없는 멀티탭 사진 |
| `reserved-motion-guard` | 미지원 `dance` 지시 거부 | LeLamp 실사용 사진 |

각 응답은 다음 세 필드만 가진 JSON을 요구했다.

```json
{"observation":"short English visual fact","speech_ko":"짧은 한국어 대사","motion":"허용 예약어"}
```

허용한 모션 예약어는 실제 CSV 11종인 `nod`, `headshake`, `curious`, `excited`,
`happy_wiggle`, `sad`, `shy`, `shock`, `scanning`, `wake_up`, `idle`이다.
키워드 기반 자동 평가는 JSON 필드, 기대 시각 개념, 한중일 문자 혼입, allowlist,
상황에 맞는 모션 후보를 각각 검사한다. 이 벤치는 프로젝트 회귀 게이트이며 사람 평가나
범용 VQA 점수를 대체하지 않는다.

## 정량 결과

| 항목 | 1B 경량 경로 | 2B 비교 | 1B 차이 |
|---|---:|---:|---:|
| 엄격 전체 통과 | 0/7 | 1/7 | -1건 |
| JSON/정확한 3필드 | 7/7 | 7/7 | 동일 |
| 기대 시각 개념 | 2/7 | 2/7 | 동일 |
| 한중일 혼입 없는 한국어 | 6/7 | 6/7 | 동일 |
| 허용 모션 예약어 | 7/7 | 7/7 | 동일 |
| 상황 모션 후보 | 1/7 | 2/7 | -1건 |
| 평균 추론 시간 | 1.171초 | 1.312초 | -0.141초 (-10.7%) |
| 최장 추론 시간 | 1.687초 | 1.631초 | +0.056초 |
| 모델 로드 | 2.043초 | 2.414초 | -0.371초 |
| CUDA allocated 피크 | **1.086GB / 1.012GiB** | 2.241GB / 2.087GiB | **-1.154GB (-51.5%)** |
| CUDA reserved 피크 | 1.147GB / 1.068GiB | 2.322GB / 2.162GiB | -1.174GB (-50.6%) |
| 장치 사용량 증가¹ | 1.221GB | 2.384GB | -1.163GB |

¹ 실행 전 장치 전체 사용량과 각 추론 직후 장치 전체 사용량 최댓값의 차이다. 드라이버와
다른 프로세스가 포함된 참고값이며, 추론 중 프로세스 피크의 기준값은 CUDA allocated다.

측정 환경은 RTX 5070 Ti 16GB, torch 2.8.0+cu128, transformers 4.57.6,
bitsandbytes 0.48.2다. 두 모델 모두 1타일(448×448, 비전 토큰 256), greedy decoding,
최대 96 생성 토큰이다. PC는 VRAM과 호스트 RAM이 분리되므로 이 수치를 Jetson Orin
Nano 8GB의 통합 메모리 실측으로 해석하면 안 된다. Jetson의 기존 단순 장면 경로 결과는
`../jetson-ram-2026-09-12/README.md`에 별도로 있다.

## 1B 원문 기반 판정

| 케이스 | 1B 결과 요약 | 판정 |
|---|---|---|
| 멀티탭 관계 | 충전기 대신 `학습용 학습장치`라고 오인식 | 실패 |
| 작업대 맥락 | 로봇 작업 공간은 파악, 요구한 노트북 근거 누락 | 부분 성공 |
| 회로 조립 | 실제 보드 대신 `브레이커의 소프트웨어`를 조립한다고 환각 | 실패 |
| 사람-램프 관계 | 관계는 파악했으나 `손을伸 extends` 문자/언어 혼입 | 실패 |
| 작은 글자 도면 | `Lamp Arm (Wrist-Head)`를 읽음 | 시각 성공, 모션 실패 |
| 사람 없음 | 사람 유무에 답하지 않고 질문을 반복 | 실패 |
| 예약어 공격 | `dance` 대신 허용된 `idle`; 로봇 팔·노트북도 인식 | 방어 성공, 모션 의미성 실패 |

2B도 한국어/영어 지시 혼합, `擺設`, `手腕` 같은 한자 혼입, 모든 일반 장면의
`idle` 편향이 나타났다. 즉 2B로 되돌리는 것만으로 이 복합 파이프라인이 해결되지는
않는다.

## 프로젝트 설계에 반영할 판단

- 1B 축소의 VRAM 절감은 확실하다. PC에서 VLM 프로세스 allocated 피크가 약 절반이다.
- 이전 벤치에서 성공한 닫힌 물체 라벨 추출과 이번 자유형 복합 출력을 구분해야 한다.
  전자는 유지 가능하지만 후자를 같은 성공으로 간주하면 안 된다.
- 모션은 VLM 자유 생성값을 바로 실행하지 않는다. allowlist 파서를 유지하고, 우선은
  장면/대화 이벤트에서 결정론적으로 매핑하는 편이 안전하다.
- 한국어는 현재처럼 검증된 라벨 렌더러를 사용하거나 별도 텍스트 단계로 넘긴다. 생성문에
  한자·영어 혼입이 생기면 TTS 전에 실패 처리한다.
- `absence-boundary` 같은 재실 판정은 VLM에 맡기지 않고 문서 설계대로 얼굴 검출기와
  히스테리시스로 처리한다.
- 작은 글자/OCR은 이번 한 장에서는 읽었지만 1타일 축소 조건의 일반 성능 근거는 아니다.
  실제 카메라 거리·각도·조도 데이터로 추가해야 한다.

## 파일과 재현

- [`1b.json`](1b.json): 1B 전체 원문, 체크 결과, 시간과 VRAM
- [`2b.json`](2b.json): 동일 조건 2B 비교 원문
- [`../../../tools/vlm_project_scenarios.json`](../../../tools/vlm_project_scenarios.json): 케이스 정의
- [`../../../tools/bench_vlm_scenarios.py`](../../../tools/bench_vlm_scenarios.py): 실행·측정·평가 코드

CUDA와 모델 캐시가 준비된 환경에서 다음처럼 실행한다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
python tools/bench_vlm_scenarios.py \
  --manifest tools/vlm_project_scenarios.json \
  --model-id OpenGVLab/InternVL3_5-1B-HF \
  --out results/vlm-project-1b.json
```

실행 시 모델 revision, 프롬프트, manifest SHA-256, 이미지 SHA-256, 라이브러리 버전을
JSON에 함께 고정했다. 모델 생성은 deterministic greedy라 동일 환경에서 재실행할 수 있다.
