# Talking Lamp 진행 순서

**팀 PIXS** | v0.3 | [파트-분배.md](파트-분배.md) v0.5 기준

> 날짜가 아니라 **순서**로 정리한 문서. 기간이 확정되면 이 순서 위에 주차를 얹으면 된다.
> ★ 표시는 **다른 파트가 기다리는 항목** — 늦어지면 그 파트가 멈춘다.

## 1. 전체 단계

| 단계 | 내용 | 이 단계가 끝났다는 기준 |
| --- | --- | --- |
| **0. 착수** | LeLamp 원본 검증 + 아키텍처·부품·모델 확정 | **LeLamp 원본 조립·MuJoCo 시뮬레이션 구동 확인**(전원 참여), VLM 후보 결정, 하드웨어 부품 발주 완료, 런타임 스키마 확정 |
| **1. 단독 동작** | 각 파트가 혼자 돌아가는 상태 | 음성 왕복 / 검출→타겟점 / 서보 궤적(시뮬레이션 또는 실물) / 기성 보드 결선·구동이 각각 성공 |
| **2. 1차 통합** | 파이프라인 관통 | **S2**(호명 → 시선 → 대화)가 처음부터 끝까지 동작 |
| **3. 전 시나리오** | 기능 완성 | S1·S3·S4·S5·S6 모두 동작 |
| **4. 완성** | 외형·시연 | 조립 완료, 시연 영상 촬영, 출품 준비 |

## 2. 파트별 순서

### E · 이수혁 (움직임+하드웨어+IK엔진) — **가장 먼저 움직여야 하는 파트**

원래 모션과 하드웨어는 다른 담당자였지만, 이제 한 사람이 둘 다 맡는다. **자체 PCB 설계를 빼고 기성 부품 조합으로 가기로 하면서 순서가 크게 단순해졌다** — 발주 리드타임이 임계 경로에서 사라졌고, "회로 설계하느라 모션 개발이 멈추는" 구간도 없어졌다. 부품은 초반에 한 번 주문해두고, 배송을 기다리는 동안 시뮬레이션에서 모션 개발을 계속하면 된다.

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | LeLamp 3D 파일(`.3mf`)·OnShape CAD·조립 문서 확보 | |
| 2 | LeLamp + lelamp_runtime 클론 → **MuJoCo 시뮬레이션 구동 확인** | 하드웨어 0개로 착수. **가장 먼저 시작할 것** |
| 3 | **★ 부품 선정·발주** — 기성 버스 서보 드라이버 보드, 서보용 전원 공급기, 서브 MCU 개발보드, 퓨즈, 마이크 어레이 | **배송 대기 동안 5~9번을 진행**하므로 일찍 주문할 것 |
| 4 | 범용 서보 드라이버로 **원본 그대로 1세트 출력 → 조립·서보 구동 검증** | **개조 전 기준점 확보** |
| 5 | 서보 통신 계층 포팅 확인 (`feetech-servo-sdk`+`lerobot` 재사용) | 서보 1개만 있으면 실물 검증 가능 |
| 6 | 100 Hz 궤적 생성기 — LeLamp 30fps에서 상향, **시뮬레이션에서 먼저 개발** | 속도 제한은 잠정값 |
| 7 | 역기구학(IK) — 5축 해, 가동범위·특이점 처리, **시뮬레이션에서 검증** | 실물 불필요 |
| 8 | 모션 블렌더 (우선순위·전환 규칙) — **시뮬레이션에서 검증** | 실물 불필요 |
| 9 | L1 칼만 필터 추종 (얼굴) | D(비전)의 검출 결과 필요 |
| 10 | L0 아이들 모션 (호흡·미세 시선) | **여기까지가 "실물 없이 되는 일"** |
| 11 | 서보 전압·토크 예산 산출, 헤드 무게 예산 확정 (조명·방열 추가분 반영, LeLamp 5V 대비 승급 검토) | |
| 12 | 전원 구성 확정 — **Jetson 19V 어댑터 + 서보용 공급기 분리**, 공통 접지·퓨즈·인러시 대책 | 회로 설계가 아니라 기성품 조합·배선으로 해결 |
| 13 | LampBase 재설계(OnShape 개조) — Jetson + 히트싱크 + **기성 보드 여러 장**이 들어가도록 확대 | 공간 부족 시 외부 유닛 분리 검토 |
| 14 | 작업 조명 하우징 설계 | D(비전)의 광학 요구사항 필요 |
| 15 | 개조분 3D 출력 → Jetson + 기성 보드로 재조립 → 서보 구동 재확인 | |
| 16 | 헤드 무게·토크 실측(조명 포함) → **본인의 모션 속도·가속 한계에 반영** | 예전엔 "D가 E를 기다리는" 인계였지만, 이제는 본인 내부 순서 문제 |
| 17 | 조명 모듈 제작·방열 | |
| 18 | 외형 조립·**배선 정리** | 보드가 여러 장이라 배선량이 많다. 전원 참여 |
| 19 | 마감·보강 (무게추/스프링 등) | |
| 20 | 모션 저작 도구, 프리미티브 라이브러리 보완, 모션 품질 튜닝 | **끝이 없는 작업 — 시간 날 때마다 계속** |

### B · 시스템통합 (담당: 김태현) — **런타임 골격이 1번**

런타임 골격이 먼저다. 이게 늦으면 A·C·D·E가 각자 따로 만들고, 통합 때 전부 뜯어고치게 된다.

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | 이벤트 스키마 정의 + 런타임 골격 설계 | |
| 2 | **★ 런타임 스텁 배포** | A·C·D·E가 이걸 상대로 개발 시작 |
| 3 | 시나리오 중재기 (S1~S6 우선순위) | |
| 4 | barge-in(말 끊기) 조율 — A(인지) 요청 취소 + E(이수혁) 모션 인터럽트를 동시에 발행 | TTS 정지 자체는 C(음성)가 감지·실행 |
| 5 | 지연 예산 계측·배분 | |
| 6 | 통합 조율 | 후반 내내 |

### A · 인지 (담당: 주경태) — **벤치마크가 1번**

VLM이 Jetson에서 얼마나 느린지를 모르면 메모리 예산도, 모델 크기도 못 정한다. 여기서 결과가 나빠야 아키텍처를 바꿀 시간이 있다.

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | **★ VLM 후보 벤치마크** (속도·메모리·한국어) | 모델은 주경태가 결정 |
| 2 | 온보드 구동 + 양자화 | |
| 3 | **★ 행동 태그 스키마 + 파서** | B(시스템통합)가 라우팅에, E(이수혁)가 재생에 필요 |
| 4 | 시스템 프롬프트·페르소나 설계 | |
| 5 | S3 자연어 조명 의도 파싱 | |
| 6 | 시나리오 평가셋 구축 | 프롬프트 수정 시 회귀 검증용 |
| 7 | **S5 발화 억제 정책** | 나머지가 다 돌아야 판단 가능 → 마지막 |
| 8 | 프롬프트 튜닝 | |

## 3. 파트 간 인수인계 순서

순서대로 나와야 뒤가 막히지 않는다.

| 순번 | 넘기는 쪽 | 받는 쪽 | 산출물 | 늦어지면 |
| --- | --- | --- | --- | --- |
| 1 | **A** | 전체 | VLM 벤치마크 결과 | 메모리 예산·모델 크기 확정 불가 |
| 2 | **B** | A·C·D·E | 런타임 스텁 + 이벤트 스키마 | 각자 따로 만들다 통합 때 충돌 |
| 3 | **D** | E | 조명 광학 요구사항 (광량·배광각·색온도) | E가 조명 모듈 발주 못 함 |
| 4 | **E** | — | 하드웨어 부품 발주 | 배송 지연 = 실물 검증 지연 |
| 5 | **A** | B·E | 행동 태그 스키마 | B가 라우팅 못 하고 E가 태그 재생 못 함 |
| 6 | **D** | E | 3D 타겟점 인터페이스 | S1 조명 배치 불가 |
| 7 | **C** | E | 소리 방향(DOA) | S6 불가 |

> 예전엔 "E(하드웨어)→D(모션) 헤드 무게·토크 실측값"도 인계 항목이었지만, 이제 둘 다 이수혁 한 명이라 **인계가 아니라 본인 작업 순서 문제**가 됐다 (2절 E 파트 16번 참고).

## 4. 통합 순서

시나리오를 한꺼번에 붙이지 말고 아래 순서로 하나씩 관통시킨다.

| 순번 | 대상 | 참여 | 왜 이 순서인가 |
| --- | --- | --- | --- |
| 1 | **S2** 호명 → 시선 → 대화 | B·C·A·E | 음성→인지→모션 **전 구간을 관통하는 최소 시나리오**. 여기서 막히는 건 전부 구조 문제 |
| 2 | **S1** 조명 자동 배치 | D·E | 조명 하드웨어가 나온 뒤에 가능 |
| 3 | **S3·S4** 자연어 조명 제어 / 자리 비움 | A·D | S1·S2가 돌아야 위에 얹힘 |
| 4 | **S6** 소리 방향 추종 | C·E | AEC·DOA가 안정된 뒤 |
| 5 | **S5** 상황 인식 자연 발화 | A | 전부 돌아가야 "적절한 타이밍"을 판단할 수 있음 |
| 6 | 전체 리허설 → 시연 촬영 | 전원 | |

## 5. 순서상 주의점

- **부품은 초반에 한 번에 주문한다.** 자체 PCB를 만들지 않으므로 발주 리드타임 리스크는 사라졌지만, 부품이 없으면 실물 검증을 못 한다. 배송을 기다리는 동안 시뮬레이션 작업(2절 E 파트 6~10번)을 진행하면 대기 시간이 낭비되지 않는다.
- **LeLamp 원본 검증(E 4번)을 건너뛰지 말 것.** 원본이 동작하는 걸 먼저 확인해야, 이후 문제가 생겼을 때 개조 탓인지 원본 탓인지 가릴 수 있다.
- **배선 정리를 얕보지 말 것.** PCB 한 장으로 통합하지 않은 대신 베이스 안에 보드가 여러 장 들어간다. Jetson + 히트싱크만으로도 공간이 빠듯한 상황이라, LampBase 재설계(E 13번) 단계에서 실제 부품 치수를 재서 배치를 확정해야 한다.
- **B의 런타임 스텁이 A·C·D·E의 출발선이다.** 완성품이 아니라 껍데기라도 먼저 나와야 한다.
- **AEC와 모션 튜닝은 예상보다 오래 걸린다.** 이 둘은 순서상 뒤에 있지만 착수는 앞당기는 게 안전하다.
- **S5는 마지막에 붙인다.** 다른 게 다 돌아가야 "언제 말을 걸어야 자연스러운지"를 판단할 수 있고, 잘못 발동하면 인상이 크게 나빠진다. 오프 스위치를 함께 만든다.
- **조립·배선·무게 실측은 전원 참여.** 이수혁 담당이지만 이 구간은 손이 많이 필요하다.
