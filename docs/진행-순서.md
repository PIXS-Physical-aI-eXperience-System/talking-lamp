# Talking Lamp 진행 순서

**팀 PIXS** | v0.7 (2026-09-07) | [파트-분배.md](파트-분배.md) v0.8 기준

> 날짜가 아니라 순서로 정리한 문서임. 기간이 확정되면 이 순서 위에 주차를 얹으면 됨
> ★ : 다른 파트가 기다리는 항목. 늦어지면 그 파트가 멈춤
> ✅ : 완료된 항목
> 항목은 **굵직한 단위**로만 적음. 세부 작업 순서는 각 담당자가 알아서 정함

**변경 이력** (계획·기능 변경만 기록함)

- 시나리오를 4개로 축소. 자연어 조명 제어(구 S3)와 상황 인식 자연 발화(구 S5) 제외
- 하드웨어 발주·조립을 순차 진행으로 반영. 조립이 마지막 단계가 아님
- 모든 물품 발주를 D(김아현)가 진행하는 것으로 확정

---

## 1. 전체 단계

| 단계 | 내용 | 이 단계가 끝났다는 기준 |
| --- | --- | --- |
| **0. 착수** | 아키텍처·부품·모델 확정 | MuJoCo 시뮬레이션 구동 확인, VLM 후보 결정, 하드웨어 부품 발주 완료, 런타임 스키마 확정 |
| **1. 단독 동작** | 각 파트가 혼자 돌아가는 상태 | 음성 왕복 / 검출에서 타겟점까지 / 서보 궤적 / 기성 보드 결선·구동이 각각 성공 |
| **2. 1차 통합** | 파이프라인 관통 | S2(호명 → 시선 → 대화)가 처음부터 끝까지 동작 |
| **3. 전 시나리오** | 기능 완성 | S1·S4·S6 모두 동작 |
| **4. 완성** | 외형·시연 | 마감 완료, 시연 영상 촬영, 출품 준비 |

하드웨어는 부품이 입고되는 대로 조립을 이어가므로, 조립이 마지막 단계에 몰리지 않음.

## 2. 파트별 순서

### E · 움직임 + 하드웨어 + IK엔진 (담당: 이수혁)

- 가장 먼저 움직여야 하는 파트임
- 부품 입고를 기다리는 동안 시뮬레이션에서 모션 개발을 진행하고, 입고되는 대로 조립을 이어감

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | ✅ LeLamp 기구·CAD·MuJoCo 시뮬레이션 확보 | 하드웨어 0개로 착수함 |
| 2 | ✅ 모션 스택 (100 Hz 궤적 · IK · 블렌더 · L1 칼만 · L0 대기 모션) | 실물 없이 되는 일은 여기까지이며 완료됨 |
| 3 | ✅ 부품 선정 | 발주는 D(김아현)가 진행함 |
| 4 | 실물 서보 구동 | 통신 계층 포팅, 시뮬 백엔드 교체, 프리미티브 11종 부호·크기 매핑 |
| 5 | 전원·배선 구성 | Jetson 19V / Pi 5 / 서보 12V 분리, 퓨즈, Ethernet 직결, 안전 정지 경로 |
| 6 | 조명 하우징 설계와 보드 외부 유닛 구성 | 기구는 원본 그대로 사용. 보드는 베이스 밖에 배치해 케이블로 연결 |
| 7 | 조명 모듈 제작·방열 | |
| 8 | 실측 반영과 마감 | 헤드 무게·토크 실측 후 모션 한계에 반영, 배선 정리, 보강. 전원 참여 |
| 9 | 모션 품질 튜닝 | 저작 도구, 프리미티브 보완. 시간 날 때마다 계속함 |

### B · 시스템통합 (담당: 김태현)

- 런타임 골격이 1번임
- 이게 늦으면 A(주경태)·C(최승원)·D(김아현)·E(이수혁)가 각자 따로 만들고, 통합 때 전부 뜯어고치게 됨

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | **★ 이벤트 스키마 정의와 런타임 스텁 배포** | 완성품이 아니라 껍데기라도 먼저. 나머지 넷의 출발선 |
| 2 | 2보드 이벤트 버스 설계 | Pi와 Jetson에 걸쳐 이벤트가 오감. 상태머신 실행 위치도 여기서 결정 |
| 3 | 시나리오 중재기와 barge-in 조율 | S1~S6 우선순위. A(주경태) 요청 취소와 E(이수혁) 모션 인터럽트를 동시 발행 |
| 4 | 지연 예산 계측·배분 | |
| 5 | 통합 조율 | 후반 내내 |

### A · 인지 (담당: 주경태)

- 벤치마크가 1번임
- VLM이 Jetson에서 얼마나 느린지를 모르면 메모리 예산도 모델 크기도 정할 수 없음

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | ✅ VLM 후보 벤치마크 후 InternVL3.5-2B 확정 | |
| 2 | VLM 측정 보완 | 응답 속도(첫 토큰까지), 라이선스 백본 확인, 탈락 근거 기록 |
| 3 | **★ 행동 태그 스키마와 파서** | B(김태현)가 라우팅에, E(이수혁)가 재생에 필요함 |
| 4 | 시스템 프롬프트·페르소나 설계 | LeLamp의 영어 전용 지시를 걷어내고 말투·성격을 새로 씀 |
| 5 | 온보드 구동·최적화와 언어 혼입 필터 | 중국어·일본어 혼입을 안 거르면 C(최승원)의 TTS가 깨짐 |
| 6 | 평가셋 구축과 프롬프트 튜닝 | |

### C · 음성 (담당: 최승원)

| 순번 | 작업 | 비고 |
| --- | --- | --- |
| 1 | ✅ TTS 확정(MeloTTS ONNX int8)과 웨이크워드 교체 판정 | `pvporcupine`은 유료 전환·인터넷 키 인증으로 사용 불가 |

| 9 | C(최승원) | E(이수혁) | 소리 방향(DOA)과 측정 오차(칼만 노이즈 파라미터) | S6 불가. E가 칼만을 튜닝하지 못함 |

## 4. 통합 순서

시나리오를 한꺼번에 붙이지 말고 아래 순서로 하나씩 관통시킴.

| 순번 | 대상 | 참여 | 왜 이 순서인가 |
| --- | --- | --- | --- |
| 1 | S2 호명 → 시선 → 대화 | B(김태현)·C(최승원)·A(주경태)·E(이수혁) | 음성에서 인지, 모션까지 전 구간을 관통하는 최소 시나리오임 |
| 2 | S1 조명 자동 배치 | D(김아현)·E(이수혁) | 조명 하드웨어가 나온 뒤에 가능 |
| 3 | S4 자리 비움·복귀 | D(김아현)·E(이수혁) | S1·S2가 돌아야 위에 얹힘 |
| 4 | S6 소리 방향 추종 | C(최승원)·E(이수혁) | AEC·DOA가 안정된 뒤 |
| 5 | 전체 리허설과 시연 촬영 | 전원 | |

---

## 5. 순서상 주의점

- **부품은 초반에 한 번에 주문함**
  - 배송을 기다리는 동안 시뮬레이션 작업(2절 E 파트 2번)을 진행하면 대기 시간이 낭비되지 않음
- **B(김태현)의 런타임 스텁이 A(주경태)·C(최승원)·D(김아현)·E(이수혁)의 출발선임.** 완성품이 아니라 껍데기라도 먼저 나와야 함
- **AEC와 모션 튜닝은 예상보다 오래 걸림.** 이 둘은 순서상 뒤에 있지만 착수는 앞당기는 게 안전함
