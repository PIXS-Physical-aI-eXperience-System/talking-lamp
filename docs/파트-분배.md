## 1. 주제 소개

Talking Lamp는 책상 위에 놓이는 관절형 AI 로봇 스탠드다. 카메라와 마이크로 주변 상황을 인식하고, 이를 바탕으로 스스로 판단해 고개를 돌리거나 조명 위치·밝기를 조절하고 음성으로 대화한다.

핵심 동작은 세 가지다.

- **조명 자동 배치** : 사용자가 책상 위에 책·키보드 등을 놓으면, 그 위치를 인식해 스스로 조명 각도를 맞춘다. 눈부심과 손 그림자를 피하는 방향을 계산해서 접근한다.
- **음성 대화** : 호명하면 고개를 돌려 사용자를 보고, 한국어로 자연스럽게 대화한다.
- **표정·반응 모션** : 대화 중, 대기 중에도 고개 끄덕임·미세 시선 이동 등으로 "살아있는" 느낌을 준다.

모든 AI 추론(영상 인식, 음성 인식·합성, 대화 판단)은 Jetson Orin Nano 8GB 보드 위에서 단독으로 처리된다. 인터넷 연결이나 외부 서버 없이 완전히 독립적으로 동작한다.

## 2. 아키텍처

### 2.1 아키텍처 도식화

시스템은 응답 속도가 다른 4개 레이어로 나뉜다. 모델 추론(대화 판단)은 초당 1회 이하로만 가능하지만, "살아있다"는 느낌은 100 ms 안에 반응해야 나온다. 그래서 빠른 반사와 느린 인지를 물리적으로 분리한다.

| 레이어 | 역할 | 주기 | 모델 사용 여부 |
| --- | --- | --- | --- |
| **L3 기능** | 조명 자동 배치 (검출 + 기하 계산) | 이벤트 발생 시 | ❌ (검출기만) |
| **L2 인지** | 상황 인식 + 대화 (통합 VLM) | 0.3~0.5 Hz | ✅ |
| **L1 반사** | 얼굴·소리 방향 추종 (칼만 필터) | 50 Hz | ❌ |
| **L0 아이들** | 호흡·미세 시선 등 기본 모션 | 항상 | ❌ |

네 레이어의 출력은 **모션 블렌더**에서 우선순위에 따라 합성되어, **100 Hz 궤적 생성기**를 거쳐 서보모터로 나간다.

### 2.2 아키텍처 파트별 구성

개발은 5개 파트로 나누고, 1인 1파트로 담당한다. 기구·서보 저수준 기반은 LeLamp 오픈소스에서 재사용하고([계획서.md의 "LeLamp 기반 전환 상세"](계획서.md) 참조), 그 위에서 동작하는 온보드 AI·비전·모션 지능은 전부 새로 만든다.

| 파트 | 담당자 | 담당 레이어/영역 | 하는 일 | 비중 |
| --- | --- | --- | --- | --- |
| **A. 인지** | 주경태 | L2 | VLM으로 상황을 판단하고, 대사·행동 태그를 만들고, 자연어 조명 제어(S3)·먼저 말 걸기(S5) 여부를 결정한다 | 15% |
| **B. 시스템통합** | 김태현 | 전 레이어를 가로지르는 조율 | 전체 상태(대기/청취/사고/발화)를 관리하고, 여러 시나리오가 겹칠 때 우선순위를 정리하고(교통정리), 메모리 등 자원을 배분하고, 동작을 기록한다 | 21% |
| **C. 음성** | 최승원 | L2 음성 입출력 | 마이크로 듣고 텍스트로 바꾸고, 대답을 음성으로 합성해 말하고, 스피커 소리가 마이크로 되돌아오는 걸 지우고(에코 제거), 소리가 난 방향을 추정한다 | 18% |
| **D. 비전** | 김아현 | L3 | 카메라로 물체·얼굴 위치를 찾아 3D로 환산하고, 조명이 향할 목표 지점과 밝기·각도를 계산한다 | 16% |
| **E. 움직임+하드웨어+IK엔진** | 이수혁 | L0 + L1 + 블렌더 + 서보 + 전 레이어 공통 하드웨어 기반 | 관절 각도를 계산하고(역기구학), 부드러운 움직임을 만들고(칼만 필터·모션 블렌더), 서보모터를 직접 구동하며, 전원·기구·조명 등 하드웨어 전체를 구성·조립한다 | 30% |

**이수혁의 작업량(30%)은 나머지 네 명 평균(약 17.5%)의 거의 2배다.** LeLamp 재사용으로 하드웨어·모션의 저수준 작업(서보 통신, 3D 기구, 프리미티브 원형, MuJoCo 시뮬레이션) 부담이 줄었고, **자체 PCB 설계를 범용 부품 구성으로 대체**하면서 한 사람이 맡을 수 있는 수준이 되었다. 상세는 4.5절.

> **자체 PCB 설계는 범위에서 제외한다.** 서보 구동은 기성 버스 서보 드라이버 보드(USB 연결, LeLamp이 쓰는 것과 동일), LED 제어는 서브 MCU 개발보드, 전원은 Jetson 19V 어댑터와 서보용 공급기를 각각 기성품으로 분리해 구성한다. 회로 설계·발주·리비전에 드는 시간과 리드타임 리스크를 없애고, 이수혁이 IK·모션 개발에 집중할 수 있게 하는 것이 목적이다. 대신 베이스 내부에 보드가 여러 개 들어가므로 **공간·배선 정리 부담은 늘어난다.**

**논의 필요 사항 (아직 미반영)**

아래는 사양을 더 엄밀하게 다듬을 수 있는 후보들이다. 지금 문서는 이 내용을 반영하지 않은 상태이며, 팀 논의 후 채택 여부를 정한다.

- 메모리 예산을 "모델 파일 크기 합산" 대신 프로세스 피크 RSS 기준으로 재현실화하고 상한 게이트를 두는 안
- 시나리오 성공 기준을 정성적 서술 대신 P95 등 정량 수치로 바꾸는 안
- 행동 태그 출력 형식을 구체적 JSON schema로 고정하는 안
- S5 발동 규칙(쿨다운·상한 등) 세부화
- 웨이크워드 코드·가중치 라이선스를 별도로 검증해야 한다는 지적
- AEC를 far-end reference 기반 구조(WebRTC APM 등)로 구체화하는 안
- 전역 상태머신을 더 세분화하는 안
- 모션 블렌더를 "우선순위+관절마스크+TTL+전환엔벌로프" 방식으로 구체화하는 안
- 헤드 무게·토크를 계산식으로 미리 검증해보자는 제안 (250g가 이미 위험 구간일 수 있다는 지적)

### 2.3 전체 파이프라인 · 데이터 흐름

```
  카메라 ─┬─▶ 검출기 ─┬─ 얼굴 위치 ──▶ [L1 반사] 칼만필터 추종 ──┐
          │           └─ 물체 위치 ──▶ [L3 기능] 기하 계산 ──────┤
          │                                                       │
          └─▶ 이미지 1장 ──┐                                     │
                            ▼                                     │
  마이크 ──┬─ 방향 추정 ──▶ [L1] ──▶  [L2 인지]  통합 VLM        │
           │                          입력: 이미지 + 텍스트        │
           └─ 잡음제거 ─▶ 음성인식 ──┘  출력: 대사 + 행동 태그    │
                                          │           │            │
                                          │대사        │태그        │
                                          ▼           ▼            │
                                       음성합성    모션 재생기 ─────┤
                                          │                        │
  [L0 아이들] 호흡 · 미세 시선 ───────────────────────────────────┤
                                                                   ▼
                                                  ┌──────────────────────┐
                                                  │   모션 블렌더          │
                                                  │  (레이어 간 우선순위)  │
                                                  └───────────┬──────────┘
                                                              ▼  관절 각도값
                                                  ┌──────────────────────┐
                                                  │  궤적 생성기 100 Hz    │
                                                  └───────────┬──────────┘
                                                              ▼
                                                     서보모터 5축 + 조명
```

**설계 원칙**

- 레이어 간 주고받는 값은 **절대 관절 각도**로 통일한다. 속도나 상대 변위를 섞으면 블렌딩 단계가 지저분해진다.
- VLM은 "무엇을 할지"만 결정하고, "어떻게 움직일지"는 미리 만들어둔 모션(프리미티브)이 재생한다. 그래야 모션 품질을 코드가 아니라 파라미터 조정만으로 다듬을 수 있다.
- 카메라 처리, 음성 처리, 모션 루프는 서로 다른 스레드로 분리한다. 하나가 다른 하나를 막으면 서보가 떨린다.

**메모리 배분** (Jetson 8GB 기준, 단위 GB)

| 항목 | 할당 | 비고 |
| --- | --- | --- |
| OS + 기본 환경 | 1.5 | |
| 통합 VLM (L2) | 2.4 | |
| 음성 인식 | 0.25 | |
| 음성 합성 | 0.2 | |
| 검출기 (L3) | 0.3 | **[임시]** 모델 선정 후 확정 |

## 3. 시나리오 구성

| ID | 시나리오 | 입력 조건 | 기대 행동 | 성공 판정 |
| --- | --- | --- | --- | --- |
| **S1** | 작업 조명 자동 배치 | 책·노트·키보드가 책상 위 임의 위치에 놓임 | 물체 위치 인식 → 조명 각도 계산 → 정렬. 손 그림자 반대편에서 접근, 얼굴 방향 눈부심 회피 | 대상면이 충분히 밝아지고, 얼굴 쪽은 눈부시지 않으며, 3초 내 정렬 완료 |
| **S2** | 호명 → 시선 → 대화 | 웨이크워드 발화 | 얼굴 방향으로 고개 회전 → 한국어 대화 → 발화 중 미세 시선·끄덕임 | 응답 시작까지 지연이 짧고, 얼굴을 정확히 향함 |
| **S3** | 자연어 조명 제어 | "좀 더 밝게" / "왼쪽 비춰줘" / "눈부셔" | 발화 의도를 해석해 조명 파라미터·자세 반영 + 음성 확인 | 의도대로 반영되고 반응이 즉각적 |
| **S4** | 자리 비움 / 복귀 | 사용자가 화면에서 사라짐(일정 시간) / 재등장 | 조명 서서히 소등 + 대기 자세 → 복귀 시 고개 들고 인사 | 몸을 잠깐 숙인 정도로는 오작동하지 않음 |
| **S5** | 상황 인식 자연 발화 | 주변 상황 변화 감지 | 먼저 말을 걺 (예: "아직 작업 중이시네요") | 상황에 맞는 발화, 불필요한 발화 최소화 |
| **S6** | 소리 방향 추종 | 시야 밖에서 소리 발생 | 소리 방향으로 고개 회전 | 방향을 정확히 향하고 반응이 빠름 |

**참고**

- **S5**는 상황 판단이 틀리면(엉뚱한 순간에 말을 검) 인상이 크게 나빠지는 시나리오다. 발동 조건을 엄격하게 잡고, 필요시 끌 수 있는 스위치를 둔다.
- **S6** 채택으로 마이크는 방향 추정이 가능한 어레이 타입이 필요하다.

## 4. 아키텍처 파트별 구체화

각 파트가 실제로 무엇을 주고받는지, 무엇이 정해졌고 무엇이 남았는지 정리한다.

### 4.1 파트 A · 인지 (담당: 주경태)

L2(인지) 레이어를 담당한다. 이미지 1장과 변환된 텍스트를 받아 VLM으로 상황을 판단하고, 대사와 행동 태그를 만든다. "무엇을 말하고 무엇을 할지"를 결정하는 두뇌 역할에 집중하고, 전체 실행 순서 지휘는 B(시스템통합)가 맡는다.

**주고받는 것**

- B(시스템통합)로부터 음성 인식이 끝난 텍스트를 받는다 (호출 시점은 B가 결정)
- B(시스템통합)에 TTS로 읽을 대사와 행동 태그를 함께 돌려준다 (B가 대사는 C로, 태그는 E로 나눠 보낸다)
- D(비전)로부터 조명 배치가 끝났다는 신호를 받아, 필요하면 확인 발화를 만들 수 있다 (선택 사항)

**확정된 부분**

- 조명 자동 배치(L3)는 학습 모델 없이 검출 + 기하 계산으로 구현한다 — 인지 파트가 관여하지 않는다
- VLM 입력은 이미지 1장 + 텍스트 한 줄이다 (실시간 영상 스트림이 아니다)
- VLM 출력은 자연어 대사 + 행동 태그다 (관절 각도를 직접 만들지 않는다)
- 상용 사용 가능한 라이선스(Apache 2.0 등)의 모델만 쓴다

**주요 과제**

- **VLM 모델 선정** — 주경태(A)가 최종 결정한다. 아래 조건을 만족하는 모델 중에서 고른다.
  - 이미지 1장 + 텍스트 한 줄을 입력받아 자연어 대사 + 행동 태그를 출력할 수 있을 것
  - 상용 사용 가능한 라이선스일 것 (예: Apache 2.0 — Qwen2.5-VL-3B-Instruct처럼 Qwen Research License인 모델은 제외 대상)
  - 크기는 **2B급을 기준선**으로 검토하고, 메모리 여유가 있을 때만 4B로 승급 검토
  - 한국어 대화 품질이 충분할 것
- 온보드 구동 → 양자화·최적화 → 속도/메모리 벤치마크
- 행동 태그 스키마 설계와 파서 (출력이 깨졌을 때 복구하는 방법 포함)
- 시스템 프롬프트·페르소나(말투·성격) 설계
- S3 자연어 조명 의도 파싱 ("좀 더 밝게", "눈부셔" → 조명 파라미터 변화량)
- S5 발화 억제 정책 — 언제 먼저 말을 걸지 판단하는 규칙. 잘못 발동하면 인상이 크게 나빠지므로 보수적 임계값 + 오프 스위치 필수
- 시나리오 평가셋 구축 — 프롬프트를 고칠 때마다 회귀 검증용

**미확정된 부분**

- 행동 태그 형식 (예: 문장에 `<nod>` 같은 표시를 섞는 방식 등)
- S5 발동 조건의 구체적 임계값

### 4.2 파트 B · 시스템통합 (담당: 김태현)

전체 시스템의 실행 순서를 지휘하는 런타임을 소유한다. A(인지)·C(음성)·D(비전)·E(이수혁)가 서로 직접 부르지 않고 전부 B의 런타임을 거쳐 연결된다. 각 파트가 따로 만들다가 통합 시점에 전부 뜯어고치는 상황을 막는 것이 이 파트의 존재 이유다.

**주고받는 것**

- C(음성)로부터 변환된 텍스트를 받아 A(인지)에 전달하고, A의 출력(대사+행동 태그)을 받아 대사는 C로, 태그는 E로 나눠 라우팅한다
- D(비전)·E(이수혁)의 상태 이벤트(조명 배치 완료, 재실 변화 등)를 구독해 시나리오 발동·중단을 중재한다
- 레이어 간 통신 규칙(이벤트 스키마)을 직접 정의하고, 나머지 파트는 이를 따른다

**확정된 부분**

- 레이어 간 통신은 B가 정의한 이벤트 스키마를 따른다
- 음성 인식 → 대화 판단 → 음성 합성 전 과정은 온보드로만 처리한다 (클라우드 미사용)

**주요 과제**

- 이벤트 버스 / 스레드 분리 구조 설계 — 카메라·음성·모션 루프가 서로를 막지 않도록
- 전역 상태머신 (대기 / 청취 / 사고 / 발화 / 작업)
- 시나리오 중재기 — S1~S6가 동시에 발동할 때의 우선순위 규칙 (예: S6 소리 추종 중 S2 호명이 들어오면?)
- 지연 예산 계측 도구 — 단계별 소요 시간 프로파일링 및 예산 배분
- **말 끊기(barge-in) 조율** — C(음성)가 사용자의 끼어든 발화를 감지하면, B가 A(인지)의 진행 중인 요청을 취소하고 E(이수혁)에 모션 중단 신호를 보내는 로직을 동시에 실행한다. TTS 출력 자체를 멈추는 동작은 C가 맡고, "지금이 진짜 끼어든 상황인지 판단해서 나머지에 알리는" 조율 로직을 B가 갖는다
- 이벤트 규칙과 런타임 뼈대(스텁)를 가장 먼저 내놓아야 A·D·E가 이를 상대로 개발을 시작할 수 있다 — 착수 1순위

**미확정된 부분**

- 전체 응답 지연의 단계별 배분값
- Jetson 8GB 메모리 배분(VLM 2.4GB·음성인식 0.25GB·음성합성 0.2GB·검출기 0.3GB 등)의 최종 확정 시점

### 4.3 파트 C · 음성 (담당: 최승원)

마이크 원음을 텍스트로, A(인지)가 만든 대사를 음성으로 바꾸는 입출력 계층을 담당한다. 음성이 모든 인터랙션의 시작점이자 지연의 병목이 되는 지점이다.

**주고받는 것**

- E(이수혁)의 마이크·스피커 하드웨어를 사용한다
- 변환한 텍스트를 B(시스템통합)에 전달하고, B로부터 받은 대사를 TTS로 출력한다
- 추정한 소리 방향(DOA)을 E(이수혁)의 L1(칼만 필터 추종)에 전달한다 — S6 시나리오의 입력

**확정된 부분**

- 음성 인식 모델은 최소 기준(경량 등급) 이상을 사용한다
- 웨이크워드는 LeLamp의 `pvporcupine`을 재사용한다 (온보드 동작 확인됨)

**주요 과제**

- 웨이크워드 감지, 발화 종료 판정(VAD)
- 에코 제거(AEC) — 없으면 스피커에서 나오는 자기 목소리에 반응한다. 난이도가 가장 높은 축이라 일정 여유가 필요하다
- 마이크 어레이 빔포밍 + 도래각(DOA) 추정 — S6 소리 방향 추종의 입력
- STT/TTS 스트리밍 처리 — 첫 음절까지의 시간(TTFB) 단축
- **barge-in 감지 및 TTS 즉시 정지** — 사용자의 발화 겹침을 인식해 TTS 출력을 바로 멈춘다. 이후 A 요청 취소·E 모션 인터럽트는 B(시스템통합)가 이어받는다

**미확정된 부분**

- 웨이크워드 호출어를 한국어로 할지 영어로 할지 (한국어 미지원 시 대체 라이브러리 검토)
- VAD 라이브러리 및 임계값 튜닝
- AEC 방식 (소프트웨어 처리 / 마이크 모듈 내장 기능 활용)
- 음성 합성 엔진 — 한국어 음질을 직접 듣고 실측 후 확정

### 4.4 파트 D · 비전 (담당: 김아현)

카메라로 물체 위치를 찾아 3D로 환산하고, 조명이 향해야 할 목표 지점과 조명 파라미터를 계산한다. 학습 없이 계산으로만 처리하며, 관절 각도로 바꾸는 일(역기구학)은 E(이수혁)가 맡으므로 D의 출력은 3D 타겟점 + 조명 조건까지다.

**주고받는 것**

- E(이수혁)의 카메라 하드웨어를 사용한다
- 계산한 3D 타겟점·조명 파라미터를 E(이수혁)에게 넘긴다 (E가 IK를 풀어 관절 각도를 만든다)
- 얼굴 검출 결과는 E(이수혁)의 L1(칼만 필터 추종) 입력으로도 공급한다
- 조명 배치 완료·재실 변화 등 상태 이벤트를 B(시스템통합)의 런타임으로 발행한다

**확정된 부분**

- 램프가 책상에 고정되어 있다는 조건을 이용해, 책상 평면 정보로 카메라 영상 속 위치를 3차원으로 환산한다
- 조명 배치는 "밝기를 최대화하고 눈부심을 최소화"하는 계산 문제로 정의한다 (학습이 아닌 수식으로 해결)

**주요 과제**

- 카메라 캘리브레이션 절차 수립 및 내부 파라미터 산출
- 책상 평면 등록 방식 (초기 설치 시 1회 등록 UX 포함)
- 검출기 선정 → Jetson 배포·최적화 (얼굴용/사물용 분리 여부 결정)
- 2D 검출 결과 → 3D 좌표 환산
- 조명 배치 최적화 — 대상면 조도 최대화, 얼굴 방향 눈부심 회피, 손 그림자 반대편 접근을 목적함수로 정식화
- **조명 광학 요구사항 산출** — 필요 광량·배광각·색온도를 수치로 내어 E(이수혁)에게 전달한다. E가 조명 부품을 발주하려면 이 수치가 먼저 나와야 한다
- S4 자리 비움/복귀 판정 — 몸을 잠깐 숙인 정도로는 오작동하지 않는 시간·신뢰도 기반 히스테리시스 설계
- 검출 실패 시 폴백 동작

**미확정된 부분**

- 물체 검출 모델 선정 (사람 얼굴용과 사물용을 나눌지 여부)
- 책상 평면 등록 방법의 구체적 절차
- S4 판정 임계 시간

### 4.5 파트 E · 움직임 + 하드웨어 + IK엔진 (담당: 이수혁)

저수준 반사(L1 얼굴·소리 추적), 상시 대기 모션(L0), 행동 태그의 실제 재생, 그리고 이 모든 것이 동작할 물리적 기반(전원·회로·기구·조명)까지 전부 담당한다. 원래는 모션과 하드웨어 두 파트였지만, LeLamp 오픈소스 재사용으로 두 영역의 저수준 작업 부담이 크게 줄어 한 사람이 맡는 구조로 통합했다.

**LeLamp 재사용** — 3D 기구 파일(`.3mf` 7종)과 조립 문서, Feetech 서보와 서보 통신 계층(`feetech-servo-sdk`+`lerobot`), 모션 프리미티브 CSV 11종, MuJoCo 시뮬레이션을 그대로 가져와 출발점으로 쓴다. 시뮬레이션 덕분에 실물 서보·3D 출력물 없이도 IK·모션 블렌더 개발을 먼저 시작할 수 있다. 다만 LeLamp은 CSV를 30fps로 그냥 재생하는 구조라 IK·칼만필터·모션 블렌더·100Hz 궤적 생성기는 전부 신규 구현이다. 상세는 [계획서.md의 "LeLamp 기반 전환 상세"](계획서.md).

**주고받는 것**

- D(비전)로부터 3D 타겟점을 받아 역기구학(IK)으로 관절 각도를 산출한다
- B(시스템통합)의 런타임을 통해 행동 태그를 받아 프리미티브를 재생하고, 인터럽트 요청도 여기서 받는다
- D(비전)의 얼굴 검출 결과와 C(음성)의 소리 방향(DOA)을 L1 입력으로 사용한다
- C(음성)에 마이크·스피커를, D(비전)에 카메라를 제공한다 (신호 처리는 각 파트가 직접 담당)

**확정된 부분**

- 미리 만들어둔 짧은 동작(모션 프리미티브)을 조합해 표현 모션을 구현한다
- 얼굴 위치 추적에는 칼만 필터를 사용해 검출 노이즈를 제거하고 부드러운 움직임을 만든다
- 레이어 간 인터페이스는 절대 관절 각도로 고정한다
- 메인 보드는 Jetson Orin Nano 8GB (전원 19V DC 배럴 5.5×2.5mm, center positive, 45W급)
- 로봇 몸체는 LeLamp 5축 구조·`.3mf`를 개조한다 (베이스·커버·암 3종·헤드·디퓨저 원본 확보)
- 서보모터는 Feetech STS3215 계열, 데이지체인 배선 (LeLamp과 동일)
- 카메라는 단안이면 충분하다 (깊이 카메라 불필요 — 기하 계산으로 위치를 구하기 때문)
- 마이크는 USB 접속 방식의 방향 추정 가능한 어레이 타입을 쓴다
- LED(표정 표현)는 Jetson에서 `rpi-ws281x`가 동작하지 않으므로 서브 MCU(ESP32/STM32)로 제어를 위임한다

**주요 과제 — 움직임**

- L1 칼만 필터 추종(얼굴+소리 방향), L0 아이들 모션(호흡·미세 시선) — 신규
- 역기구학(IK) — 5축 구조에서 타겟점을 향하는 관절 해 산출, 특이점·가동범위 처리 — 신규
- 모션 프리미티브 라이브러리 — LeLamp CSV 11종(끄덕임·갸웃·인사·기상 등)을 원형으로 시나리오에 맞게 보완
- 모션 블렌더 — 레이어 우선순위, 전환(크로스페이드) 규칙 — 신규
- 100Hz 궤적 생성기 — 속도·가속 제한, 저크 억제 — LeLamp의 30fps 재생 루프에서 상향
- 서보 통신 계층 — `feetech-servo-sdk`+`lerobot` 그대로 재사용, 온도·부하 모니터링·안전 정지만 보강
- 모션 저작 도구 — 코드 수정 없이 파라미터(YAML 등)만으로 동작을 튜닝할 수 있는 환경
- **말 끊기(barge-in) 대응** — B(시스템통합)가 보내는 모션 인터럽트 신호를 받아, 재생 중인 프리미티브를 즉시 멈추고 대기/경청 자세로 부드럽게(크로스페이드) 전환하는 기능을 모션 블렌더 설계 초기 단계부터 넣어둔다

**주요 과제 — 하드웨어**

- **부품 선정·조달** — 기성 버스 서보 드라이버 보드, 서보용 전원 공급기, 서브 MCU 개발보드, 인라인 퓨즈. 자체 PCB를 만들지 않으므로 이 조합으로 필요한 기능이 다 커버되는지 먼저 확인한다
- **전원 구성** — Jetson 19V 어댑터와 서보 계통을 물리적으로 분리하고 공통 접지 처리, 인러시·전압 강하 대책. 회로를 새로 그리는 대신 기성품 조합과 배선으로 해결한다
- LampBase 재설계 — Jetson + 히트싱크 + **여러 장의 기성 보드**가 들어가도록 확대. 안 들어가면 외부 유닛 분리도 검토
- 서보 전압·토크 예산 산출 — 조명·방열이 추가되면 헤드 무게가 늘어나므로 5V 구동보다 승급(7.4V/12V) 검토
- 작업 조명 모듈 및 방열 설계 — LeLamp의 LED는 표정 표현용이라 실제 조명 자체가 없어 완전 신규로 만든다
- 마이크 어레이 장착 위치 — 스피커와의 거리가 곧 에코 제거(AEC) 난이도이므로 C(음성)와 협의
- 헤드-베이스 배선 재설계 — 조명 전류·카메라 신호가 추가되면 LeLamp의 이더넷 케이블 1가닥 구성을 그대로 못 쓴다
- **조립·배선 경로 정리** — PCB 한 장으로 통합하지 않은 만큼 보드 간 배선이 늘어난다. 베이스 내부 배치와 케이블 정리가 이전보다 중요해진다

**진행 순서 관련 확인 사항**

- **PCB 리드타임이 사라져 시뮬레이션(IK·모션) 작업을 초반에 몰아서 할 수 있다.** 부품만 주문해두면 배송을 기다리는 동안 MuJoCo에서 IK·블렌더 개발을 계속 진행할 수 있으므로, 하드웨어와 모션이 서로를 막지 않는다
- 헤드 무게를 실측해서 그 결과를 본인의 모션 속도·가속도 한계 계산에 반영하는 시점을 스스로 잡는다 (예전에는 서로 다른 담당자 간 "인계"였지만, 이제는 한 사람의 내부 작업 순서 문제다)

**미확정된 부분**

- 모션 프리미티브 목록 및 개수
- 모션 저장 포맷 및 저작 도구의 형태
- 레이어 동시 발생 시 합성 규칙(우선순위/전환)
- 칼만 필터 세부 파라미터 튜닝
- 관절 속도·가속 제한값 (헤드 무게 실측 결과에 종속)
- 서보모터 전압 사양 (홀딩 토크 여유와 직결)
- 헤드 무게 상한 (임시 250g 상한 설정 중, 조명·방열 추가로 초과 가능성 높음)
- Jetson이 LampBase에 안 들어갈 경우 외부 분리 여부
- LED 제어를 서브 MCU로 넘길지, SPI 방식(NeoPixel_SPI)으로 Jetson에서 직접 처리할지
- 기성 부품(서보 드라이버·전원 공급기·서브 MCU) 구체 모델 선정

> **참고 문헌** — ELEGNT(arXiv:2501.12493, 프로젝트 폴더 내 PDF 확보)가 기능적 목적과 표현적 요소를 결합한 램프형 로봇의 움직임 설계를 다루고 있어 직접 참고할 수 있다. EMOTION(arXiv:2410.23234)도 LLM 기반 표현적 제스처 생성 참고 사례로 활용 가능하다.

## 5. 파트 ↔ 인력 매핑

| 파트 | 담당자 |
| --- | --- |
| A. 인지 | 주경태 |
| B. 시스템통합 | 김태현 |
| C. 음성 | 최승원 |
| D. 비전 | 김아현 |
| E. 움직임+하드웨어+IK엔진 | 이수혁 |

- **김태현(B)은 시스템통합·런타임을 쥐므로 통합 조율 역량이 특히 중요하다.** 프로젝트 후반 통합 병목이 될 수 있는 자리다.
- **이수혁(E)의 작업량은 30%로 나머지 네 명 평균(약 17.5%)의 거의 2배다.** 자체 PCB 설계를 범위에서 뺀 만큼 부담이 줄었으나 여전히 가장 무거운 파트이므로, 부담이 커지면 조립·배선처럼 손이 많이 가는 구간은 다른 파트가 돕는다 (4.5절 참고).
- **김아현(D)과 이수혁(E)은 조명 광학 요구사항·3D 타겟점을 주고받는 관계라 소통 빈도가 높다.**
- 통합 주차 및 3D 출력물 조립·배선·무게 실측은 파트 배정과 무관하게 **전원 참여**.
