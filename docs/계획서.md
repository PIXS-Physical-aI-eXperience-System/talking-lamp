## 1. 팀 소개

팀 PIXS는 AI 모델 개발, 컴퓨터 비전, 하드웨어 설계, IoT 등 서로 다른 전문 분야를 보유한 5명으로 구성된 융합형 팀입니다. 특히 소프트웨어와 하드웨어를 모두 아우르는 팀 구성이 본 프로젝트의 핵심 강점으로, AI 추론부터 비전, 서보 제어, 기구·전원 구성까지 외주 없이 팀 내에서 전 과정을 자체 수행할 수 있다는 강점이 있습니다.

**소프트웨어**
김아현, 김태현, 주경태, 최승원은 VLA(Vision-Language-Action) 관련 논문을 공동 집필한 경험을 바탕으로 온보드 VLM 구동 및 최적화, 비전·공간 인지, Voice 파이프라인 구축, 시스템 통합을 담당합니다.

- **김아현** — 제8회 AI ROBOTICS 융합 아이디어 경진대회 대상, 제1회 양팔로봇 활용 Physical AI 해커톤 대회 로보시지상, IT 페스티벌 은상
- **김태현** — 제8회 AI ROBOTICS 융합 아이디어 경진대회, 제1회 양팔로봇 활용 Physical AI 해커톤 대회 공동 수상
- **주경태** — 대학(원)생 창업 아이디어 경진대회 최우수상, 한국지식경영학회 추계학술대회 장려상, LG Aimers 8기 수료
- **최승원** — VLA 관련 논문 공동 집필 참여

**하드웨어**
이수혁은 선형·비선형 칼만필터, ORB-SLAM, 자율주행 및 위치 추정 등 로봇 시스템 전반에 걸친 깊은 기술적 역량을 보유하고 있으며, 팀 내 하드웨어 분야 핵심 전력으로서 역기구학·모션 제어, 서보 구동, 전원·기구 구성 전반을 담당합니다.

- **이수혁** — 제2회 CO-SHOW 4족보행로봇 경진대회 한국AI로봇산업협회장상·단장상, 제8회 AI ROBOTICS 융합 아이디어 경진대회 우수상 등 로봇 분야 대외 수상 다수

팀 PIXS는 논문 공동 집필과 다수의 경진대회 참가를 통해 이미 협업 역량을 검증하였으며, 소프트웨어와 하드웨어의 균형 잡힌 팀 구성을 바탕으로 Talking Lamp의 기획부터 제작까지 전 과정을 자체적으로 수행할 수 있는 역량을 갖추고 있습니다.

## 2. 지원동기 및 목표

### 배경

- 대부분의 AI 서비스는 스마트폰·PC 화면 안에 국한되어 있으며, 물리적 공간에서 사용자와 자연스럽게 상호작용하는 Physical AI 기반 생활 로봇 시장은 초기 단계에 머물러 있음
- 2025년 미국 스타트업 Interaction Labs가 공개한 감성 인터랙션 로봇 스탠드 'Ongo'는 글로벌 수요를 입증했으나 아직 상용 출시 전이며, 국내에는 유사 제품이 전무한 상황
- 팀 PIXS는 VLA 관련 논문 공동 집필 및 다수의 AI·로봇 경진대회 수상 경험을 바탕으로, 보유 기술을 융합한 국내 최초 온보드 Physical AI 인터랙션 램프 로봇 "Talking Lamp" 개발을 목표로 함

### 목적 및 개발 내용

- 카메라로 주변 상황 인식 → VLM이 대사와 행동을 결정 → 서보모터로 물리적 반응, 조명 자동 배치, 음성 대화 수행하는 온보드 시스템 구현
- 클라우드 없이 Jetson Orin Nano에서 AI 추론을, Raspberry Pi에서 실시간 로봇 제어를 수행하는 완전 온보드 분산 구조 실현
- 빠른 반사(얼굴·소리 추종)와 느린 인지(대화 판단)를 레이어로 분리해, 생성형 AI의 지연과 무관하게 즉각 반응하는 인터랙션 제공

### 필요성

- 1인 가구 증가(2024년 기준 35% 돌파), 재택근무 확산으로 개인 공간에서의 AI 컴패니언 수요 급증
- 클라우드 의존 AI 제품의 개인정보 유출 우려가 높아지며 온디바이스 AI 제품의 신뢰도 및 선호도 상승
- 온보드 VLM을 생활 밀착형 램프 로봇에 적용한 국내 사례 전무, 기술적 선점 기회 존재

### 목표

- 완전 동작하는 Talking Lamp 프로토타입 완성 및 시연 영상 제작
- 전국 규모 경진대회 출품 (임베디드SW, AI, 로봇 분야)
- 프로그램 등록 및 특허 출원 검토

## 3. 프로젝트(아이템) 개요 및 핵심기술

### 아이템 개요

Talking Lamp는 책상 위에 놓이는 관절형 AI 로봇 스탠드로, 카메라와 마이크로 주변 상황을 인식하고 VLM(Vision-Language Model)이 대사와 행동을 결정하여 고개를 돌리거나 조명을 배치하고 음성으로 대화하는 생활 밀착형 Physical AI 컴패니언이다. AI 추론은 Jetson Orin Nano에서, IK·모션 합성·서보 제어는 Raspberry Pi에서 처리되며 두 보드는 유선 로컬 네트워크로 연결되어 인터넷 없이 완전 동작한다.

### 핵심기술

- **온보드 VLM (Vision-Language Model)** : 카메라 이미지 1장과 음성 인식 텍스트를 입력받아 상황을 판단하고, 한국어 대사와 행동 태그를 함께 생성. 커스텀 학습 없이 상용 가능 라이선스(Apache 2.0 등) 사전학습 모델을 양자화해 사용하며, 2B급을 기준선으로 두고 메모리 여유 시 승급 검토
- **온보드 추론 통합** : Jetson Orin Nano 8GB 위에서 VLM + 음성 인식(STT) + 음성 합성(TTS) + 비전 검출기를 동시 구동. 8GB를 CPU·GPU가 공유하는 구조이므로 모델 파일 크기가 아닌 **프로세스 피크 메모리** 기준으로 예산을 관리하고, 양자화·GPU 작업 직렬화로 최적화
- **4계층 반응 구조** : 대화 판단(VLM)은 초당 1회 이하로만 가능하지만 "살아있다"는 느낌은 100ms 내 반응이 필요하므로, Jetson의 조명 배치(L3)·인지(L2) 결과를 Pi의 반사 추종(L1)·아이들 모션(L0)과 합성. Pi가 모션 블렌더와 100 Hz 제어 루프를 상시 실행
- **칼만 필터(KF) 기반 서보 제어** : 5축 관절(Base Yaw / Base Pitch / Elbow Pitch / Wrist Roll / Wrist Pitch)에 대해 얼굴 검출 노이즈를 KF로 제거하고, 역기구학(IK)으로 조명 목표점을 관절 각도로 변환해 부드러운 궤적 생성
- **단안 카메라 기반 3D 공간 인지** : 램프가 책상에 고정된 조건을 이용해, 등록된 책상 평면과 카메라 광선의 교차로 물체 위치를 3차원으로 환산. 깊이 카메라 없이 기하 계산만으로 조명 목표점 산출
- **Voice 파이프라인** : 웨이크워드 → 에코 제거(AEC) → 음성 인식 → VLM → 음성 합성 전 과정 온보드 처리. 마이크 어레이의 도래각(DOA) 추정으로 시야 밖 소리 방향 추종 지원
- **기성 부품 기반 하드웨어 구성** : 자체 PCB를 설계하는 대신 검증된 기성 부품을 조합해 회로 설계·발주 리스크를 제거. 서보 드라이버와 LED는 Raspberry Pi에 연결하고, Jetson·Pi·서보 전원 계통을 분리 구성
- **IoT 연동 (본체 완성 후 확장)** : ESP32 + MQTT 기반 앱 연동. 프로토타입 필수 범위가 아닌 확장 목표로 두어, 본체의 온보드 자율 동작을 우선 완성한 뒤 진행

### 수행 단계

1. **착수·설계** : LeLamp 원본 조립·MuJoCo 시뮬레이션 검증, 시스템 아키텍처 확정, VLM 후보 벤치마크, 하드웨어 부품 선정·발주, 런타임 이벤트 스키마 확정
2. **단독 동작** : Jetson의 Voice·비전 파이프라인 구동, Raspberry Pi의 IK·모션 블렌더·100 Hz 실기 제어 구동, 검출→3D 타겟점 변환, 전원·서보 결선 검증
3. **통합** : 온보드 VLM 구동·양자화, 행동 태그 파이프라인 연결, 시나리오별 순차 통합(호명·대화 → 조명 배치 → 나머지), 헤드 무게 실측 반영
4. **완성** : 외형 조립, 전체 통합 테스트, 시연 영상 제작, 경진대회 출품 준비 (여유 시 IoT 앱 연동)

#### 2. 하드웨어 변경

##### H1. Raspberry Pi 모션 제어기 + Jetson 추론 장치 **[필수]**

LeLamp의 Raspberry Pi 제어 구조를 유지하고 Jetson을 AI 추론 장치로 추가한다. Pi는 램프 가까이에서 서보·LED와 100 Hz 루프를 소유하고, Jetson은 VLM·STT·TTS·비전 결과를 고수준 이벤트로 전달한다.

| 구분 | Raspberry Pi | Jetson Orin Nano 8GB |
| --- | --- | --- |
| 역할 | IK, L0/L1, 모션 블렌더, 100 Hz 궤적, Feetech, LED | VLM, STT/TTS, 비전, 시나리오 판단 |
| 연결 | 서보 드라이버 USB, LED GPIO, Jetson과 유선 LAN | 카메라·마이크·스피커, Pi와 유선 LAN |
| 전원 | Pi 전원 + 서보용 별도 전원 | 19V DC 배럴 5.5×2.5mm, center positive, 45W급 |
| 배치 | LampBase 내부 또는 바로 옆 | 외부 연산 유닛을 기본으로 하며 방열·팬 공간 확보 |

**할 일**

- **[필수]** Pi·Jetson·서보 전원 계통을 분리하고 필요한 신호 접지만 공통화
- **[필수]** 두 보드 사이 유선 네트워크와 재연결·하트비트 정책 확정
- **[필수]** Jetson은 모션 이름·3D 목표·중단 이벤트만 전송하고, 원시 관절 명령과 서보 포트는 Pi만 소유
- **[검토]** Jetson 팬 소음이 마이크에 유입되는지 확인 — 유입 시 배치 이격 또는 음성 잡음 제거 보강

##### H2. LED 제어 방식 **[중요]**

LeLamp의 `rpi-ws281x`는 Raspberry Pi에서 계속 사용할 수 있다. 프로토타입은 Pi 직접 제어를 기본으로 하고, 작업 조명 전류·채널 수 또는 실시간성 요구가 커질 때만 ESP32/STM32 개발보드로 분리한다.

##### H3. 마이크: ReSpeaker Pi HAT → USB 마이크 어레이 **[필수]**

마이크와 음성 파이프라인은 Jetson이 소유하므로 USB 접속 방식의 마이크 어레이를 사용한다.

- **[필수]** USB 접속 방식의 마이크 어레이로 교체
- **[검토]** DOA(방향 추정) 지원 여부를 구매 전 반드시 확인 — S6 시나리오의 입력
- **[검토]** 장착 위치는 스피커와 최대한 이격 (거리가 곧 AEC 난이도)

##### H4. 카메라 마운트 수정 **[필수]**

- Pi Camera 기준 헤드를 선정 카메라(IMX219 CSI 또는 동급 단안 광각)에 맞게 수정
- 카메라는 Jetson에 연결하고, **[검토]** CSI 커넥터 규격·JetPack 드라이버 호환 확인

##### H5. 작업 조명 추가 — **LeLamp에 없는 기능** **[필수]**

LeLamp의 LED 매트릭스(64구)는 **표정 표현용**이다. 책을 비추는 조명이 아니다.

- **[필수]** 헤드에 작업용 광원 + 방열 구조 신규 설계
- **[필수]** 비전 파트의 광학 요구사항(광량·배광각·색온도) 반영
- **[중요]** **헤드 무게 예산 250g 재검토** — 광원과 방열판이 추가되면서 기존 예산을 넘길 가능성이 높다

##### H6. 서보 전압 재검토 **[중요]**

LeLamp은 서보를 **5V 2A**로 구동한다. STS3215의 정격(7.4V/12V 계열)보다 낮게 쓰는 구성이라 토크 여유가 적다.

- H5의 조명·방열이 헤드에 추가되면 **홀딩 토크가 부족할 수 있다**
- **[검토]** 7.4V 또는 12V 계열 STS3215로 승급 검토 (STS3215는 7.4V 19.5kg / 12V 30kg 등 여러 변형 존재)
- **[필수]** 헤드 실측 무게 확정 후 토크 재계산 → 그 결과를 모션 파트의 속도·가속 한계에 반영

##### H7. 헤드-베이스 배선 재설계 **[중요]**

LeLamp은 **이더넷 케이블 1가닥**에 전력과 데이터를 함께 실어 보낸다. 작업 조명 전류와 Jetson 연결이 추가되므로 헤드 내부 배선과 보드 간 네트워크를 분리 설계한다.

- **[검토]** 조명 전류가 추가된 상태의 전압 강하 계산
- **[검토]** 카메라(CSI/USB) 신호를 관절을 통과시켜 배선하는 경로 확보

#### 3. 소프트웨어 변경

##### S1. AI 스택 전면 교체 — **이 프로젝트의 핵심** **[필수]**

LeLamp의 `main.py`는 AI를 **전부 OpenAI 클라우드로 호출**한다.

```
livekit-agents[openai] / livekit.plugins.openai  →  제거
```

| 기능 | LeLamp | 우리 |
| --- | --- | --- |
| STT | OpenAI (클라우드) | 온보드 |
| 대화 판단 | OpenAI (클라우드) | **온보드 VLM** |
| TTS | OpenAI (클라우드) | 온보드 |
| 상황 인식 | 없음 | **온보드 VLM** |

- **[필수]** `livekit-*` 의존성 제거, 온보드 파이프라인으로 대체
- **[필수]** LeLamp의 Agent 클래스 구조는 참고만 하고 재작성

##### S2. 한국어 대응 **[필수]**

LeLamp 시스템 프롬프트에 **영어 전용 지시**가 하드코딩돼 있다 (`You ONLY speak English. Never respond in any other language, ever.`)

- **[필수]** 프롬프트 전면 재작성 (페르소나 포함)
- **[필수]** 한국어 STT/TTS 모델 선정
- **[검토]** `pvporcupine` 한국어 웨이크워드 지원 여부 확인. 미지원 시 영어 호출어를 쓰거나 대체 라이브러리 검토

##### S3. 모션 아키텍처 확장 **[필수]**

LeLamp은 **CSV를 재생**하는 구조다. 우리 설계(L0~L3 + 블렌더)와 근본적으로 다르다.

| 항목 | LeLamp | 우리 |
| --- | --- | --- |
| 제어 주기 | `MotorsService(fps=30)` | **100 Hz 궤적 생성기** |
| 동작 방식 | 녹화 CSV 단순 재생 | 레이어 합성(블렌더) |
| 추종 | 없음 | **L1 칼만 필터** |
| 관절 계산 | 없음 | **역기구학(IK)** |

- **[필수]** fps 30 → 100 Hz 상향, 궤적 생성기 신규
- **[필수]** IK·칼만 필터·모션 블렌더 신규 구현
- **[중요]** 프리미티브 CSV 11종은 재사용하되, 블렌더 입력으로 쓸 수 있게 포맷 검토
- **[필수]** 100 Hz 루프와 Feetech 연결은 Raspberry Pi에 상주. Jetson은 행동 태그·3D 목표·방향·중단 이벤트만 전송

##### S4. Jetson↔Raspberry Pi 런타임 연결 **[필수]**

- **[필수]** Pi 모션 데몬을 상시 실행하고 B의 이벤트 버스에서 `motion.play`, `motion.interrupt`, `track.point`, `track.bearing`, `task_light.place/clear`를 받음
- **[필수]** 허용된 11개 모션 이름만 실행하고 알 수 없는 태그·만료된 목표는 거부
- **[필수]** Pi가 `motion.status`로 현재 모션·busy·fault·연결 상태를 Jetson에 반환
- **[필수]** 네트워크가 끊겨도 Pi가 마지막 원시 명령을 계속 반복하지 않도록 TTL과 안전 대기 자세 적용
- **[중요]** 모션 요청은 비동기 이벤트로 전달하며 Jetson의 추론 지연이나 재시작이 Pi의 100 Hz 루프를 막지 않게 함

#### 4. 완전히 새로 만드는 것

LeLamp에 **존재하지 않아** 재사용이 불가능한 영역.

| 영역 | 내용 | 비고 |
| --- | --- | --- |
| **비전 전체** | 검출, 캘리브레이션, 평면 등록, 2D→3D, 조명 배치 최적화, 자리비움 판정 | LeLamp README는 "Computer vision via Pi Camera"라고 적혀 있으나 **저장소에 비전 코드가 아예 없다** |
| **인지 전체** | VLM 온보드 구동, 행동 태그 스키마, 프롬프트, 발화 정책, 평가셋 | |
| **모션 일부** | IK, 칼만 필터, 블렌더, 궤적 생성기, 모션 저작 도구 | 서보 제어·프리미티브는 재사용 |
| **음성/런타임 일부** | 온보드 STT/TTS, AEC, DOA, 런타임(이벤트 버스·상태머신·중재기) | 웨이크워드는 재사용 |

#### 5. 초기 설정 순서

전환 직후 이 순서로 진행한다.

| 순번 | 작업 | 목적 |
| --- | --- | --- |
| 1 | LeLamp + lelamp_runtime 저장소 클론, 문서 정독 | 구조 파악 |
| 2 | **MuJoCo 시뮬레이션 구동** | 하드웨어 없이 모션 개발 착수 가능하게 |
| 3 | OnShape CAD 원본 복사 → 팀 워크스페이스 확보 | 개조 기반 |
| 4 | BOM 대조 → 국내 조달 가능 부품 확인, 대체품 목록 작성 | 발주 준비 |
| 5 | STS3215 1개 + 드라이버로 서보 통신 검증 (PC에서, `uv sync`만) | 모션 파트의 1번 작업 착수 |
| 6 | Raspberry Pi 실물에 `lerobot`·`feetech-servo-sdk` 설치 및 100 Hz 통신 검증 | 실기 제어 리스크 조기 확인 |
| 7 | 3D 출력 1세트 (원본 그대로) → 조립·동작 확인 | **개조 전 기준점 확보** |
| 8 | Raspberry Pi·서보 드라이버 탑재 기준으로 LampBase 정리, 외부 Jetson 연결 경로 확정 | H1 |

> **7번을 건너뛰지 말 것.** 원본이 동작하는 걸 먼저 확인해야, 이후 문제가 생겼을 때 "우리 개조 탓인지 원본 탓인지"를 가릴 수 있다.

#### 6. 파트 분배에 미치는 영향

LeLamp 전환으로 하드웨어·모션 파트의 부담이 줄고 인지·비전은 그대로다. 세부 파트 구성·비중·담당자는 [파트-분배.md](파트-분배.md)를 최신 기준으로 따른다.

  https://arxiv.org/abs/2501.12493
