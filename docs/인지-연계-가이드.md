# 인지(LLM) 연계 가이드 — A파트 → 음성(C)·통합(B)

> A파트(인지)가 선정·튜닝한 온보드 LLM을 음성 파이프라인에 붙이는 방법. 읽고 그대로 실행하면 된다.

---

## TL;DR (핵심 요약)

- **모델:** HyperCLOVA X SEED 1.5B — ollama, GGUF Q4_K_M
  `hf.co/kexplo/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF`
- **엔드포인트:** `http://127.0.0.1:11434/v1/chat/completions` (OpenAI 호환, 스트리밍 O)
- **필수 설정:** `temperature = 0.2`, `keep_alive = -1` (유휴 언로드 방지)
- **연결 방법 2가지:** ① 평문(파서 없이, 스트리밍) ② JSON(파서 포함, 행동태그)
- **튜닝의 정수:** 프롬프트(`SYSTEM`/`SYSTEM_PLAIN`) + few-shot + temp 0.2 → 이 3개가 한국어 품질·환각 억제·형식 준수의 원천. **재현하려면 이 값을 그대로 쓴다.**

## 0. 환경 준비 (ollama, GPU)

⚠️ JetPack 7(L4T r39)용 ollama **컨테이너는 GPU가 안 됨**(CPU 폴백). **네이티브 설치**를 쓴다.

```bash
# 네이티브 ollama (드라이버 하위호환으로 CUDA 13.2에서 GPU 구동)
curl -fsSL https://ollama.com/install.sh | sh
# 모델 저장을 NVMe로 (eMMC 용량 부족). systemd override:
sudo mkdir -p /etc/systemd/system/ollama.service.d
printf '[Service]\nEnvironment="OLLAMA_MODELS=/mnt/ssd/ollama/models"\n' | sudo tee /etc/systemd/system/ollama.service.d/override.conf
sudo systemctl daemon-reload && sudo systemctl restart ollama
# 모델 받기
ollama pull hf.co/kexplo/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF
# GPU 확인 (PROCESSOR = 100% GPU 여야 함)
ollama run hf.co/kexplo/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF "안녕" && ollama ps
# 유휴 언로드 방지 (첫 요청 타임아웃 방지)
curl -s http://127.0.0.1:11434/api/chat -d '{"model":"hf.co/kexplo/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF","keep_alive":-1,"messages":[{"role":"user","content":"hi"}]}' >/dev/null
```

## 1. 프롬프트 2종 (둘 다 `src/cognition/cognition_run.py` 안에 있음)

| 상수 | 용도 | 출력 | 파서 | 스트리밍 | 행동태그 |
|---|---|---|---|---|---|
| `SYSTEM_PLAIN` | 평문 대화 | 자연어 | 불필요 | O | X |
| `SYSTEM` (+ `FEWSHOT`) | 구조화 | JSON | 필요 | X | O |

**중요:** `SYSTEM`(JSON)을 파서 없이 쓰면 모델이 `{"say":...}`를 뱉어 TTS가 중괄호를 읽는다.
→ **파서 없이 갈 거면 반드시 `SYSTEM_PLAIN` 을 쓴다.**

---

## 2. 연결 방법 ① — 평문 (파서 없이, 지금 바로) ★ 음성 우선 검증용

sw107 음성 파이프라인(`voice/llm.py`, `voice/agent.py`)에 그대로 붙는다.

1. `voice/llm.py` 의 `SYSTEM_PROMPT` 를 **`SYSTEM_PLAIN` 문자열로 교체** (아래 3절에서 복사).
2. 모델·온도 지정:
   - model: `hf.co/kexplo/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF`
   - temperature: `0.2`
3. 실행:
   ```bash
   python voice_agent.py --llm http://127.0.0.1:11434/v1/chat/completions
   ```
**결과:** STT → 우리 LLM(튜닝된 한국어) → TTS 스트리밍. 환각 억제·한국어 품질 유지. **행동태그는 없음.**

---

## 3. 연결 방법 ② — JSON + 파서 (행동태그 포함, 나중에)

행동태그(모터 제어)까지 필요할 때. A파트 통합모듈을 그대로 호출한다.

```python
from cognition_run import respond   # src/cognition/

r = respond(labels, user_text)      # labels = D 검출 라벨 리스트(한국어)
r.say        # → C(TTS)로
r.actions    # → E(모터)로  예: [{"tag":"nod","intensity":0.6}]
r.end_turn   # → B 상태머신
```
- `respond()`가 내부에서 **프롬프트 조립 → LLM 호출 → 파서**까지 다 함. 절대 예외 안 던짐(깨진 출력 방어).
- **스트리밍 안 됨**(JSON 전체를 받고 파싱). 지연이 문제면 방법 ①과 병행하거나, "say만 스트리밍 + 태그는 끝에" 방식을 B·C와 협의.
- 파서 단독 규칙은 `cognition_parser.py` 참고 (enum 밖 tag→idle, JSON 복구, 대사 정화).

---

## 4. 우리 프롬프트 엔지니어링을 "그대로 적용"하는 법

튜닝 결과(JSON 100%, 환각 없음)를 재현하려면 **아래 3개를 반드시 유지**한다:

1. **프롬프트 문자열** — `cognition_run.py` 의 `SYSTEM` / `SYSTEM_PLAIN` 을 **수정 없이** 사용.
2. **few-shot** — JSON 모드는 `FEWSHOT`(호명→wake_up, 동의→nod, 부정→headshake, 위로→sad, 사실거부, scanning)을 messages 앞에 붙인다. (`respond()`가 자동으로 함)
3. **temperature 0.2** — 이보다 높으면 JSON 형식이 흔들린다.

**재튜닝/재측정이 필요하면** 벤치 도구 사용:
```bash
python src/cognition/llm_bench.py \
  --url http://127.0.0.1:11434/v1/chat/completions \
  --model hf.co/kexplo/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF \
  --name HyperCLOVA-1.5B --fewshot --temp 0.2
```
→ 모드 A(대화)/B(JSON) 준수율, TTFT, tok/s, 메모리를 자동 측정. 프롬프트 바꿔가며 이 수치로 비교.

## 5. 검증된 결과 (기준선)

| 지표 | 값 (HyperCLOVA 1.5B, GPU, few-shot, temp 0.2) |
|---|---|
| JSON 행동태그 준수 | 100% |
| 환각 | 없음 (시간·물건 안 지어냄) |
| 속도 | 24 tok/s, TTFT 0.1s |
| 모델 메모리 | ~2.0GB |

실제 이미지 E2E(참고): 검출 `물병,키보드,의자,마우스,노트북` + "내 책상 어때?" → `"정리정돈이 잘 되어 있네요."` + `happy_wiggle`.

## 6. 남은 협의 (A가 열어둔 것)

- **파서 위치:** 방법 ②의 `respond()`를 sw107 파이프라인 어디서 돌릴지 (llm.py 내부 vs 별도 모듈) — B·C 결정.
- **스트리밍 vs 태그:** JSON은 스트리밍이 안 되므로, 저지연이 필요하면 "say 스트리밍 + 태그 후행" 절충 검토.
- **A↔D 라벨 형식:** D는 영어 COCO 라벨 출력. 한국어 매핑은 현재 A의 `vision_to_cognition.py`가 처리 — 누가 매핑할지 D와 확정.
- **행동태그 스키마 사인오프:** `docs/행동태그-스키마-v1.md` 기준 B·E 확인.
