## 1. 조명 자세가 어깨 서보 정격을 넘김 **[가장 급함]**

### 확인한 것

- S1 을 두 번 실행했고 두 번 다 서보 과부하 잠김이 발생함
  - 1차: 목표 `(0.395, 0.319, 0)`, 수 분 뒤 잠김
  - 2차: 목표 `(0.551, -0.029, 0)`, **약 20초** 만에 잠김 (1차 발열이 안 식은 상태로 추정)
  - 두 번 다 모터 전원 재투입으로 복구함
- E 의 MuJoCo 모델에 `TaskLightLayer.place()` 가 만든 자세를 넣고 `mj_inverse` 로 중력 유지 토크를 계산함
- 기준값은 STS3215 12V **정격 10 kg·cm = 0.98 N·m**, 스톨 30 kg·cm = 2.94 N·m

| 목표점 반경 | IK 수렴 | 어깨(base_pitch) 유지 토크 | 정격 대비 |
| --- | --- | --- | --- |
| 휴식 자세 | 해당 없음 | 0.62 N·m | 63 % |
| 15 cm | ok | 0.48 | 49 % |
| 20 cm | ok | 0.72 | 73 % |
| **25 cm** | ok | **0.94** | **96 %** (지속 가능한 한계) |
| 30 cm | ok | 1.16 | 118 % |
| 40 cm | ok | 1.58 | 161 % |
| 45 cm | ok | 1.80 | 184 % |
| 50 cm 이상 | **미수렴** | 1.79~1.83 | 183~187 % |

- 지속 유지가 가능한 목표점은 **반경 25 cm 이내뿐**임
- 접근 자세를 바꿔 피할 수 있는지 확인함. 스탠드오프 12~40 cm 와 접근 방향 수평비중 0~0.9 를 조합한 **16 가지 전부 174 % 이상**이었음
  - 78 % 가 나온 2 조합은 IK 실패 자세이며 헤드가 책상 높이로 주저앉음
- 모델 질량을 검증함. 합계 1.187 kg, 어깨 위 약 0.67 kg. `0.67 × 9.81 × 0.25 m ≈ 1.6 N·m` 로 계산값과 일치함
- **카메라는 원인이 아님.** 카메라를 빼도 1.83 N·m(187 %)이고, 카메라 30 g 의 기여는 +8 % 임

### 확인 요청

- 아래 선택지 중 무엇을 택할지. **하드웨어 추가와 기구 재제작이 불가한 전제**로 정리했으므로 폭이 좁음
  - **목표 반경을 25 cm 이내로 제한**. 조명 대상이 램프 바로 앞에 있을 때만 S1 이 동작함
  - **램프를 대상에 더 가까이 두는 배치를 전제로 명시**. 모멘트 암이 짧아지며, 시연 조건으로 문서화가 필요함
  - **유지 시간 제한**. 일정 시간 뒤 휴식 자세로 복귀하되 조명이 꺼지는 것을 감수함
- S1 정의를 조정해야 하는지. 현재 정의는 "맞추고 유지" 이므로 위 선택지 중 마지막 항목과 충돌함
- 위 선택지가 모두 받아들이기 어렵다면, 현재 구성에서 S1 이 성립하는지 자체를 함께 판단해야 함

## 2. IK 도달 범위가 D 가정과 다름

### 확인한 것

- D 의 현재 작업 범위(`vision.pipeline.Workspace`)는 반경 **0.12 ~ 0.80 m** 로 잡혀 있음
- 실측 결과 **IK 가 수렴하는 최대 반경은 0.45 m** 임
- 0.50 m 이상에서는 `converged=False` 인데도 **최선 근사 자세로 그대로 이동**하며, 팔이 뻗은 채 버티게 됨

### 확인 요청

- E 기준의 실제 도달·유지 가능 범위를 알려주면 D 의 `Workspace` 를 그 값으로 맞추겠음
- IK 미수렴 시 이동하지 않고 거절하는 편이 안전하지 않은지

## 3. 서보 잠김이 ROS 상태에 나타나지 않음

### 확인한 것

- 두 번 모두 잠긴 동안 `/lamp/motion_status` 가 `fault: None`, `busy: true` 를 유지함
- `deadline_misses` 는 5 에서 28 로 늘었다가 더 증가하지 않음
- 소프트웨어가 모터 정지를 감지할 방법이 없어 사람이 눈으로 볼 때까지 계속 가열됨

### 확인 요청

- 과부하나 토크 차단을 `fault` 또는 별도 필드로 올릴 수 있는지
- 서보 드라이버에 `Present_Temperature`, `Present_Load` 레지스터가 있음
  (`lerobot/motors/feetech/tables.py`). 이를 상태에 포함할 수 있는지

## 4. 모터 전원 재투입 후 모션 서비스 재시작이 필요함

### 확인한 것

- 모터 전원을 껐다 켠 뒤 `/dev/ttyACM0` 이 새로 생성됨
- 모션 데몬은 살아 있으나(`active`, `NRestarts=0`) 옛 핸들을 계속 잡고 있어 제어 루프가 정지함
  - 증상은 `sent_ticks: 0` 고정, `state: unknown`, 방향 상태 `connection_failed`
  - 반면 `/lamp/motion_status` 의 `connected` 는 **`true` 로 표시됨**
- `systemctl restart talking-lamp-motion.service talking-lamp-device.service` 로 복구함

### 확인 요청

- 포트를 재개방하도록 하거나, `connected` 가 실제 상태를 반영하도록 할 수 있는지

---

## 5. `place_task_light` 액션이 종료되지 않음

### 확인한 것

- 목표를 수락한 뒤 자세를 계속 유지하며 완료로 떨어지지 않음
- D 노드는 `busy` 를 "E 가 팔을 움직였다" 로 해석하므로 처리 분기가 꼬였고, D 쪽에서 우회 구현함

### 확인 요청

- 무기한 유지가 의도된 동작인지
- 완료 시점의 정의가 있는지

## 6. `active_motion` 값이 빈 문자열이 아닌 `"None"` 문자열임

### 확인한 것

- D 로그가 `E가 None 실행 중` 으로 출력됨. D 쪽에서 우회 처리함

### 확인 요청

- 의도한 값인지 확인만 부탁

## 통보: D 의 캘리브레이션이 E 의 두 가지에 의존함

### 확인한 것

- 카메라가 헤드에 장착되어 있어 관절값 없이는 좌표를 낼 수 없음
- 관절값은 Pi 밖으로 나오지 않고 `base_yaw` 만 공개되므로, D 는 관절값을 아는 유일한 자세에서만 절대 좌표를 냄
- 그 자세가 **`motion.config.REST_POSE`** 이고, **`/lamp/return_center`** 가 거기로 복귀시킨다는 전제 위에 캘리브레이션이 서 있음

### 확인 요청

- `REST_POSE` 상수를 바꿀 계획이 있으면 미리 알려주기. D 의 헤드→카메라 캘리브레이션이 무효가 되어 재측정이 필요함
- `return_center` 가 다른 자세로 가도록 바꿀 계획이 있으면 동일하게 알려주기

## 참고: D 쪽 현재 상태

- 렌즈 내부 파라미터와 헤드→카메라 변환 측정을 완료함. 보드 실측 대비 **위치 오차 중앙값 0.87 cm**, 4.2초 평균 0.57 cm
- 카메라부터 검출, 3D 좌표, `/lamp/place_task_light` 까지 전 구간 연결을 확인함
- D 가 사용하는 E 인터페이스는 `/lamp/return_center`, `/lamp/place_task_light`, `/lamp/track_point`, `/lamp/motion_status`, `/lamp/orientation_status` 임
- D 자체 토픽은 `/lamp/vision/` 이름공간에만 두었고 `lamp_interfaces` 는 변경하지 않음
