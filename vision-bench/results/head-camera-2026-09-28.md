# 헤드 카메라 초점 수정과 검출기 재비교

2026-09-28 · Jetson 온보드, `USU Camera 4K`(IMX415) 1920×1080, **램프 헤드 장착**

## 왜 다시 쟀나

9/20 측정은 전부 선명도 4 안팎의 흐린 사진으로 했다. 그 상태에서 YOLOX-s가 노트를 놓친 것처럼
보여 모델 선택을 [잠정]으로 남겨 두었다. 초점이 풀리면 다시 보기로 한 항목이다.

## 초점: 소프트웨어가 아니라 렌즈 나사 문제였다

카메라는 맨 기판 모듈에 **나사식(M12 계열) 렌즈**가 끼워진 형태다. 모터 초점이 없어서
`CAP_PROP_FOCUS` 설정이 전부 거부됐던 것이고, 드라이버가 돌려주던 `AUTOFOCUS=1`은 기본값이었을 뿐이다.
렌즈 통을 손으로 돌리면서 `tools/live.py`의 선명도를 보고 맞췄다.

| | 선명도 (라플라시안 분산) |
| --- | --- |
| 9/20 (높이별 촬영) | 3.7 ~ 4.6 |
| 9/28 조정 전 (방 전경) | 16.7 |
| **9/28 조정 후** | **202** (책 40~60 cm) |

렌즈가 진동으로 풀리지 않게 고정해야 한다. 풀리면 이 문서의 수치가 모두 무효가 된다.

## 검출 결과 (YOLOX, CPU, 임계 0.25)

사진을 눈으로 보고 실제 물건과 대조했다. 선명도 196과 128인 두 장.

| 실제 물건 | nano | tiny | **s** |
| --- | --- | --- | --- |
| 사람 | person 0.85 | person 0.86 | person 0.90 |
| 노트북 | laptop 0.77 | laptop 0.87 | laptop 0.80 |
| **노란 노트 (책상 가운데)** | 못 잡음 | keyboard 0.75 | **keyboard 0.53** |
| 헤드폰 | mouse 0.84 | mouse 0.93 | mouse 0.87 |
| 흰 바구니 | book 0.20 (임계 0.15) | **laptop 0.84** | 안 잡음 |
| 펜 | — | cell_phone 0.54 | remote 0.47 |
| 전원 어댑터 | — | — | chair 0.39 |

## 읽어낸 것

**1. s와 tiny 모두 노트를 정확히 박스친다. 이름은 `keyboard`다.** 박스 하단 중심(조명 타겟 기준점)이 노트 앞 가장자리에
찍힌다. 9/20의 "s가 노트를 놓쳤다"는 흐린 사진에서 노트가 화면 끝에 잘려 있었기 때문이다.

**2. s가 여전히 오탐이 적다.** tiny는 빈 바구니를 `laptop 0.84`로 확신했다. 조명이 빈 바구니를 비추게 되는 오류다.
→ **YOLOX-s 확정.**

**3. COCO에 없는 물건은 가장 비슷한 이름으로 불린다.** 헤드폰은 mouse, 펜은 remote나 cell_phone, 어댑터는 chair가 된다.
이 오인들은 모두 "읽거나 치는 물건"이 아니다. 그래서 **조명 대상을 `book`·`laptop`·`keyboard`로 좁혔다**
(`src/vision/labels.py`의 `TASK_LIGHT`). 노트는 남고 오인은 전부 빠진다. 인지용 라벨은 장면 전체를 그대로 넘긴다.

**4. 얼굴은 옆모습에서도 잡힌다.** YuNet 0.91, 40 ms. 대신 **옆모습에서는 눈 간격 방식이 거리를 두 배로 본다.**
눈 41 px, 박스 200 px(비율 0.21)에서 눈 기준 0.97 m, 얼굴 폭 기준 0.44 m였고 실제 거리는 약 0.5 m다.
비율이 0.30 미만이면 얼굴 폭으로 계산하도록 고쳤다(`geometry.PROFILE_RATIO`). 정면 얼굴의 비율은 약 0.45다.

## 렌즈 보정 (내부 파라미터)

보드를 인쇄하지 않고 **노트북 화면(15", 1920×1200)에 띄워** 찍었다(`calib/charuco_screen_1920x1200.png`).
내부 파라미터는 보드 크기와 무관하므로 칸 크기는 화면 크기로 계산한 37 mm를 그대로 썼다.

| | 값 |
| --- | --- |
| 초점거리 fx, fy | 705.1, 704.8 px (가로 화각 약 108°) |
| 주점 cx, cy | 1014.5, 503.6 px |
| 왜곡 k1, k2, p1, p2, k3 | 0.077, -0.098, 0.001, -0.000, 0.029 |
| 재투영 오차 | 0.146 px (30장) |

카탈로그 화각 120°로 근사하면 초점거리가 636 px이 되어 약 10% 틀린다.

**보드가 이미지 위쪽 약 55%에만 찍혔다.** 카메라가 책상 쪽으로 숙여져 있어서, 노트북을 책상에 세우면
화면이 늘 이미지 가운데보다 위에 온다. 아래쪽은 외삽이다. 외삽이 얼마나 흔들리는지 보려고
왜곡 모델을 바꿔(k3 고정) 비교했다.

- 아래쪽 가운데: 광선 방향 차이 0.4° 이하, 책상 위 점 차이 0.3 cm
- **아래쪽 모서리: 최대 15° 차이.** 이 구역의 검출은 위치가 크게 틀릴 수 있다

책상에 눕힌 보드(휴대폰 화면이나 인쇄본)로 아래쪽을 채우면 이 한계가 풀린다.

## 검출기 속도 (1920×1080, CPU, 9/29)

ROS 노드를 붙이고 나서 처음으로 실제 프레임 루프에서 쟀다. 9/20 측정과 달리 사물과 얼굴을
같은 루프에서 돌린 값이다.

| | 한 장당 |
| --- | --- |
| YOLOX-s | 611 ms |
| YOLOX-tiny | 84 ms |
| YuNet | 13 ms |

**둘 다 매 프레임 돌리면 얼굴 추적이 1.6 Hz로 떨어진다.** 책상 위 물체는 움직이지 않으므로
사물은 0.5초마다, 얼굴은 매 프레임 본다. 실측 **얼굴 33 fps, 사물 1.8 Hz**다.

## 대기 모션이 만드는 오차

E의 L0 대기 계층은 어떤 자세 위에도 흔들림을 얹는다(호흡 2.4°, 시선 1.3°, 배회 0.6°).
휴식 자세도 예외가 아니다. 대기 오프셋을 E의 FK로 재생해 책상 위 점이 얼마나 움직이는지 쟀다.

| 평균 구간 | 중앙값 | p95 | 최악 |
| --- | --- | --- | --- |
| 한 프레임 | 1.2 cm | 7.7 | 15.8 |
| 2.0 s | 0.9 cm | 5.9 | 12.6 |
| **4.2 s (호흡 1주기)** | **0.7 cm** | **3.9** | **7.4** |
| 8.4 s | 0.4 cm | 2.6 | 4.6 |

**한 장만 찍어서는 최악 17.7 cm까지 틀린다.** 흔들림은 주기적이고 평균이 0에 가까우므로 호흡 한 주기를
평균 내면 대부분 없어진다. 카메라는 계속 돌기 때문에 S1 명령이 올 때 평균은 이미 쌓여 있다. 지연은 붙지 않는다.
구현은 `vision/tracking.py`의 `ObjectAverager`.

## 헤드→카메라 변환과 실측 정확도 (9/29)

램프를 `/lamp/return_center` 로 휴식 자세에 두고, 보드를 램프 앞 45 cm 책상에 테이프로 붙여 쟀다.
정확도는 **보드 코너 24개의 실제 좌표와 파이프라인이 낸 좌표를 비교**해서 얻었다(보드는 45~62 cm 구간).

| | 결과 |
| --- | --- |
| 복원된 카메라 | 책상 위 **32.7 cm**, 아래로 **18.0°** |
| 헤드 기준 카메라 위치 | x -6.6, y -7.9, z -3.4 cm |
| 맞춤 재투영 오차 | 16.1 px (256장 동시) |
| **위치 오차 (한 장)** | **중앙값 0.87 cm**, p95 2.78, 최대 4.09 |
| **위치 오차 (4.2초 평균)** | **중앙값 0.57 cm**, p95 1.17 |
| 위치 오차 (10초 평균) | 중앙값 0.49 cm, p95 1.05 |

### 자세를 평균 내면 안 된다

처음에는 여러 장의 **카메라 자세를 평균**냈다. 결과가 더 나빠졌다.

| | 보드 코너 위치 오차 |
| --- | --- |
| 한 장으로 구한 자세 | **0.07 cm** |
| 45초치 자세를 평균낸 것 | **2.57 cm** |

평균 자세는 어느 순간과도 맞지 않는 자세다. 카메라를 얕은 각도로 책상을 보기 때문에 역투영이
강하게 비선형이고, 자세를 평균 내는 것과 결과를 평균 내는 것이 전혀 다른 값이 된다.
지금은 평균 대신 **여러 장의 픽셀 오차를 동시에 최소화하는 마운트 하나**를 찾는다(`head_camera.fit_mount`).

**책상 위 오차를 직접 최소화하는 것도 시도했고, 실패했다.** 한 평면만 보면 같은 점들을 지나는 자세가
여러 개라 거의 퇴화한다. 카메라 높이가 11.7 cm(실제 32.7)인 답으로 수렴했고 정확도도 나아지지 않았다.
픽셀 기준이 조건수가 훨씬 낫다.

**모서리가 일부만 잡힌 장은 빼야 한다.** 8개 이상이면 받아들이던 것을 24개 다 잡힌 장만 쓰도록 바꾸자
재투영 오차가 44.8 px → 16.1 px 로 떨어졌다.

### 겪은 것

- 램프가 측정 도중 **저절로 자세를 잃었다.** 모션 상태는 `idle`, `busy: false`, 오류 없음이었는데도
  카메라가 벽을 보고 있었다. `return_center` 로 복구됐고 같은 자세로 돌아왔다. 원인 미확인 — **[확인 필요]**
- 그래서 캘리브레이션은 **결과를 검증하지 않으면 조용히 틀린다.** 보드 코너와 비교하는 검증을 항상 같이 한다
