# 검출기 1차 측정 — 속도와 피크 메모리

2026-09-20 · Jetson Orin Nano 8GB 온보드

## 측정 조건

| 항목 | 값 |
| --- | --- |
| 보드 | Jetson Orin Nano 8GB, L4T R39.2, Ubuntu 24.04.4, Python 3.12.3 |
| **전력 모드** | **15 W** |
| 런타임 | onnxruntime-gpu 1.29.0 (`/home/asdf/vision-venv`) |
| 부하 상태 | **유휴.** ROS 노드 0개, 메모리 1.9 GiB 사용 중 |
| 입력 | 고정 시드(1217) 난수. 모든 조합이 같은 배열을 받음 |
| 반복 | 워밍업 8회 후 30회 측정 |
| 메모리 | `/proc/self/status` 의 `VmHWM` (피크 RSS) |

모델·프로바이더 조합마다 **별도 프로세스**로 실행했다. 한 프로세스에서 여러 개를
띄우면 피크 RSS가 누적되어 개별 예산 판단에 쓸 수 없다.

이 단계는 정확도를 재지 않는다. 속도와 메모리는 입력 내용이 아니라 크기에만
좌우되므로 난수로 충분하다.

## 읽어낸 것

**1. CUDA 피크 메모리는 모델과 무관하게 약 900 MB다.**

897 / 898 / 968 / 921 — 3.5 MB짜리 nano와 35 MB짜리 s의 차이가 71 MB뿐이다.
CUDA 컨텍스트와 cuDNN 작업공간이 전부를 지배하고 모델 가중치는 오차 수준이다.
최소 모델(conv 1개)로 따로 재본 바닥값도 598 MB였다.

→ **GPU 검출기는 [2.3절 예산](../../docs/파트-분배.md) 0.3~0.7 GB를 넘는다.**

**2. CPU는 84~190 MB로 예산에 한참 여유가 있다.**

같은 모델이 EP만 바꿔도 메모리가 5~10배 차이난다.

**3. 얼굴은 CPU로 충분하다.**

YuNet이 CPU에서 16.2 ms, 초당 62프레임이다. L1 칼만이 요구하는 30 Hz의 두 배다.
GPU와의 속도 차는 3.1 ms뿐인데 메모리는 921 MB 대 99 MB다.

**4. 사물도 CPU로 될 가능성이 높다.**

S1은 조명 배치 시점에만 도는 이벤트성이라 30 Hz가 필요 없다.
nano는 초당 33회, tiny는 12회, s도 0.3초다.

## 한계 — 이 숫자를 그대로 믿으면 안 되는 부분

- **유휴 상태에서 쟀다.** 실제로는 STT·TTS·LLM이 같이 돈다. CPU 검출기는 그 CPU를
  나눠 쓰므로 실부하에서 지연이 늘어난다. 통합 후 재측정이 필요하다
- **전력 모드 15 W 기준이다.** 모드가 바뀌면 전부 달라진다. A파트 VLM 속도 측정도
  같은 모드로 해야 나란히 놓을 수 있다
- **정확도는 재지 않았다.** 박스 하단 중심 오차, 얼굴 중심 오차, 미검출률은
  실제 촬영이 있어야 하고 카메라 마운트가 정해져야 의미가 있다
- **YOLOX는 오래된 릴리스(0.1.1rc0)다.** 같은 크기의 최신 모델보다 정확도가 낮다.
  이 측정은 "어느 급이 예산에 들어가나"를 위한 것이지 최종 모델 선정이 아니다
