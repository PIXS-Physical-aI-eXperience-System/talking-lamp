## 결정

### 1. 검출기는 CPU 에서 돌린다 **[확정]**

Jetson 에서 CUDA 세션을 열면 **모델 크기와 무관하게 피크 메모리가 약 900 MB** 다.
3.5 MB 짜리 nano(897 MB)와 35 MB 짜리 s(968 MB)의 차이가 71 MB 뿐이다.
CPU 는 같은 모델이 84~190 MB 다. [2.3절 예산](../docs/파트-분배.md)의 0.3~0.7 GB 를
GPU 구성은 만족할 수 없다.

부수 효과로 **LLM 몫이 약 0.75 GB 늘어난다** (2.55 → 3.3 GB). 3B 급과 4B 급을
가르는 차이이므로 A파트의 VLM→LLM 교체 논의에 이 수치를 전달한다.

### 2. 얼굴은 YuNet **[확정]**

CPU 에서 16.2 ms, 초당 62 회. L1 칼만이 요구하는 30 Hz 의 두 배다. 99 MB.
OpenCV 에 `cv2.FaceDetectorYN` 으로 내장되어 별도 전처리 코드가 필요 없다.

SCRFD 는 일부 사전학습 가중치가 연구용 한정이라 뺐고, MediaPipe 는 tflite
런타임을 하나 더 끌고 와야 해서 뺐다.

### 3. 사물은 YOLOX-s **[잠정]**

S1 은 조명 배치 시점에만 도는 이벤트성이라 **속도가 제약이 아니다.** CPU 281 ms
로도 충분하므로 셋 중 가장 큰 것을 쓰지 않을 이유가 없다. 190 MB 도 예산 내다.

같은 이미지에서 nano·tiny 와 비교했을 때 s 는 **검출 수는 적지만 신뢰도가 높고
박스가 쪼개지지 않는다.** tiny 가 더 많이 찾은 것들은 작은 흰 물체를 `mouse` 로
오인한 것이 섞여 있었다.

**오탐이 미검출보다 나쁘다.** 조명이 엉뚱한 곳을 비추면 바로 드러나기 때문이다.
그리고 타겟점은 박스 하단 중심 하나여야 하는데, 박스가 쪼개지면 타겟점도 둘이 된다.

> **검증 항목** — tiny 는 노란 노트를 `book 0.29` 로 잡았으나 s 는 놓쳤다.
> 노트·책은 S1 의 핵심 대상이므로, 초점이 해결된 뒤 이 한 가지를 반드시 다시 본다.
> 재현되면 s 를 버리고 tiny 로 간다.

### 4. Ultralytics(YOLOv8/v11)는 후보에서 제외 **[확정]**

AGPL-3.0 이고 이 저장소는 GPL-3.0 이다. A파트가 Qwen3-VL 을 라이선스로 탈락시킨
전례가 있어 같은 기준을 적용한다. YOLOX(Apache-2.0)로 요구가 충족되므로 분쟁
소지를 안고 갈 이유가 없다.

### 5. 카메라는 책상에 별도 고정한다 **[잠정]**

| 안 | 판정 |
| --- | --- |
| A · 책상에 별도 고정 마운트 | **채택** |
| B · 램프 Base-Elbow 링크 | 보류 |
| C · 램프 베이스 본체 | **배제** |

**C 는 측정으로 죽었다.** 책상면 위 5 cm 에서 키보드 검출 0 건이었다. 책상을
스치는 각도라 납작한 물체가 사라진다. S1 의 대상이 바로 그 납작한 것들이다.

**B 를 보류한 이유는 셋이다.**

1. **가림.** 램프 자기 몸(헤드·팔)이 화면의 30 % 가까이를 차지한다. 팔이 움직이면
   가리는 위치도 계속 바뀐다
2. **관절값 의존.** 카메라 자세를 풀려면 `base_yaw`·`base_pitch` 가 매 프레임
   필요한데 `MotionStatus.msg` 에 관절 각도가 없다. E 에게 발행을 요청해야 한다
3. **추종 발진.** 얼굴을 따라 고개를 돌리면 카메라도 함께 움직인다. 보정이 어긋나면
   "사람이 움직인 것"과 "내가 움직인 것"을 구분하지 못해 고개가 흔들린다

A 는 이 셋이 모두 없다. B 의 장점은 외관 하나뿐이다.

**필요 높이는 25 cm 이상**이다. 10~15 cm 에서는 책상 물체가 4 개, 29 cm 에서 7 개로
뛴다. 참고로 램프 휴식 자세의 팔꿈치가 29.3 cm 다.
