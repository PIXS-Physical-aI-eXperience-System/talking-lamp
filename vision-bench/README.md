## 결정

### 1. 검출기는 CPU 에서 돌린다 **[확정]**

Jetson 에서 CUDA 세션을 열면 **모델 크기와 무관하게 피크 메모리가 약 900 MB** 다.
3.5 MB 짜리 nano(897 MB)와 35 MB 짜리 s(968 MB)의 차이가 71 MB 뿐이다.
CPU 는 같은 모델이 84~190 MB 다. [2.3절 예산](../docs/파트-분배.md)의 0.3~0.7 GB 를
GPU 구성은 만족할 수 없다.

부수 효과로 **LLM 몫이 약 0.75 GB 늘어난다** (2.55 → 3.3 GB). 3B 급과 4B 급을
가르는 차이이므로 A파트의 VLM→LLM 교체 논의에 이 수치를 전달한다.

### 2. 얼굴은 YuNet **[확정]**

CPU 에서 16.2 ms, 초당 62 회. L1 칼만이 요구하는 30 Hz 의 두 배다. 99 MB.
OpenCV 에 `cv2.FaceDetectorYN` 으로 내장되어 별도 전처리 코드가 필요 없다.

SCRFD 는 일부 사전학습 가중치가 연구용 한정이라 뺐고, MediaPipe 는 tflite
런타임을 하나 더 끌고 와야 해서 뺐다.

### 3. 사물은 YOLOX-s, 조명 대상은 책·노트북·키보드 **[확정]**

S1 은 조명 배치 시점에만 도는 이벤트성이라 **속도가 제약이 아니다.** CPU 281 ms 로도 충분하다.

초점을 맞춘 뒤 다시 비교했다([head-camera-2026-09-28](results/head-camera-2026-09-28.md)).
s 와 tiny 모두 책상 가운데 노트를 정확히 박스쳤다(이름은 `keyboard`). 9/20 의 "s 가 노트를 놓쳤다"는
흐린 사진에서 노트가 화면 끝에 잘려 있었기 때문이었다. 남은 차이는 오탐이고, tiny 는 빈 바구니를
`laptop 0.84` 로 확신했다. **오탐이 미검출보다 나쁘다.** 조명이 엉뚱한 곳을 비추면 바로 드러난다.

COCO 에 없는 물건은 비슷한 이름으로 불린다(헤드폰 → mouse, 펜 → remote). 그래서 **조명 대상을
`book`·`laptop`·`keyboard` 로 좁혔다.** 노트는 남고 오인은 빠진다. 인지용 라벨은 장면 전체를 넘긴다.

### 4. Ultralytics(YOLOv8/v11)는 후보에서 제외 **[확정]**

AGPL-3.0 이고 이 저장소는 GPL-3.0 이다. A파트가 Qwen3-VL 을 라이선스로 탈락시킨
전례가 있어 같은 기준을 적용한다. YOLOX(Apache-2.0)로 요구가 충족되므로 분쟁
소지를 안고 갈 이유가 없다.

### 5. 카메라는 램프 헤드에 달려 있다 **[하드웨어 확정]**

9/21 에는 "책상 별도 고정"을 권했지만, 실제 하드웨어는 **헤드 윗테두리에 카메라 기판을 고정**한 구조다.
헤드와 함께 움직인다. 그 권고는 철회한다.

유리한 점이 있다. 휴식 자세에서 헤드가 책상면 위 **34.7 cm**, 수평 아래 약 36° 를 향한다.
9/20 높이별 측정의 기준(25 cm 이상)을 넘는다. 카메라와 조명이 같은 헤드에 있어서, 나중에 빛이
물체에 떨어졌는지 카메라로 보고 조준을 보정하는 닫힌 루프도 가능하다.

대신 **카메라 자세가 매 순간 바뀐다.** 문제는 헤드 자세를 D 가 모른다는 것이다. 5축 관절값은
Pi 안에만 있고 밖으로는 base_yaw 하나만 나온다(모든 브랜치 확인, 9/28). E 의 인터페이스가
D 에게 `lamp_base` 점을 받도록 짜인 것은 원래 설계가 고정 카메라를 전제했기 때문이다.

E 코드를 고치지 않고 D 선에서 푼다.

- **S1**: `/lamp/return_center` 로 휴식 자세에 보내고, `/lamp/motion_status` 의 `busy=false` 를 기다린 뒤 찍는다.
  휴식 자세 관절값은 상수(`motion.config.REST_POSE`)라 헤드 자세를 FK 로 계산할 수 있다.
  base_yaw 는 `/lamp/orientation_status` 의 `current_yaw` 로 보정한다
- **S2**: 마지막으로 보낸 목표점을 "헤드가 보는 곳"으로 두고, 화면에서 얼굴이 가운데서 벗어난 만큼만
  목표점을 고쳐 다시 보낸다. 조금씩 고쳐서 추종이 흔들리지 않게 한다
- **헤드→카메라 변환**은 휴식 자세에서 보드로 한 번 잰다. 카메라가 고정돼 있어 한 번이면 된다.
  사용자는 설치할 때 아무것도 등록하지 않는다. 책상은 언제나 `lamp_base` 의 z = 0 이다

## 출력 인터페이스

| 용도 | 토픽 / 액션 | 타입 | 상태 |
| --- | --- | --- | --- |
| S1 조명 타겟점 | `/lamp/place_task_light` | `lamp_interfaces/action/PlaceTaskLight` (입력 `geometry_msgs/PointStamped`) | 정의됨 |
| S2·S4 얼굴 위치 | `/lamp/track_point` | `geometry_msgs/PointStamped` | 정의됨 |
| L2 대화용 객체 목록 | `/lamp/vision/labels` | `std_msgs/String` (JSON) | D 이름공간에 임시 구현. **A·B와 타입 협의 필요** |
| S4 재실 변화 | `/lamp/vision/presence` | `std_msgs/Bool` | D 이름공간에 구현 |

`header.frame_id` 는 [2.4절 공통 규약](../docs/파트-분배.md)의 `lamp_base` 를 쓴다.
앞의 두 경로는 LLM/VLM 을 거치지 않고 Pi 모션 스택으로 바로 간다.

구현은 `jetson_ws/src/lamp_vision` 이다. E 의 `lamp_interfaces` 는 건드리지 않았다. 아직 타입이 정해지지
않은 두 개만 D 이름공간(`/lamp/vision/`)에 `std_msgs` 로 내보낸다. 협의가 끝나면 그쪽으로 옮기면 된다.
노드 구성과 실행 방법은 [src/vision/README.md](../src/vision/README.md) 의 "ROS 노드" 절에 있다.

**캘리브레이션은 9/29 에 끝냈다.** 렌즈 내부 파라미터와 헤드→카메라 변환 둘 다 측정했고,
보드 코너의 실제 좌표와 비교해 검증했다. **책상 위 위치 오차는 한 장에서 중앙값 0.87 cm,
4.2초 평균에서 0.57 cm** 다(45~62 cm 구간). S1 은 이 정확도로 돌아간다.

**렌즈 내부 파라미터는 9/28 에 측정했다.** 보드를 인쇄하지 않고 노트북 화면(15") 에 띄워 30장을 찍었다.
실제 가로 화각은 카탈로그 120° 가 아니라 **108°** 였다(재투영 오차 0.15 px). 자세한 값과 한계는
[results/head-camera-2026-09-28.md](results/head-camera-2026-09-28.md).

**카메라 초점은 9/28 에 해결됐다.** 나사식 렌즈를 돌려 선명도 4 → 202.
렌즈가 진동으로 풀리지 않게 고정해 둘 것.
